# 画面

画面是用 Remotion（React）写的：每一帧都是「成片秒数 `t`」的函数。你不用从零画东西，片场有一套积木库，画面工作主要是三件事：**想清楚每句话配什么画面、挑积木把它拼出来、让每个元素踩在该念到的那个词上。**

积木的名字、参数、用法都在积木手册里：`film\src\blocks\手册.md`（每部新片自带一份）。写场景之前把手册读完，再把积木陈列片的帧看一遍（`<片场>\_gallery\`，或自己跑 `.\film.cmd stills Gallery <秒…>`），知道每块积木长什么样。

## 一、先写分镜表

动手写代码前，在 `制作记录.md` 里列分镜表，一句一行：

```
| 句 | 念什么（缩写） | 标记 → 画面上发生什么 | 用什么积木 |
| c1 | 这张卡到底能不能订 | {card} 卡片从右侧飞入；{q} 大问号盖章 | 图片展示 + 盖章 |
| c2 | 小林 实测都订上了 | {fr} 头像贴纸；{phone} 手机框升起；{ok} 两个绿勾 | 手机框 + 核对清单 |
| q1 | （气泡）我要看的就是这步 | 小咸鱼探头 | 气泡（自动） |
```

写分镜时守这几条：

- **每个标记都要有画面变化。** 念到「三步」时三样东西一样样出来，念到「被拒」时卡片弹回去盖红章。画面只是配图、不跟着话动，观众就走神。
- **一屏只讲一件事：一个主视觉，加最多三个附属元素。** 常见的一屏：一句大标题 + 一组卡片；一个窗口 + 一个角色 + 一两个说明牌；一张图 + 一个盖章。
- **每 2–4 秒有新东西出现。** 一句话讲了八秒画面没动，就把它拆成几步出现，或者推一下镜头。
- **同一种版式不连用三次。** 三章都是「标题 + 三张卡」，观众会觉得在看幻灯片。按内容挑积木：

  | 要讲的内容 | 用哪块积木 |
  |---|---|
  | 开场的痛点、钩子 | `Hook`；片名亮相用 `TitleCard` |
  | 这期讲几件事 | `Roadmap`（换章时可以回看点亮） |
  | 每章的名字 | `ChapterTag`（常驻左上角）；章与章之间可用 `ChapterBreak` |
  | 几种方案、几个特点、几条规矩 | `CardRow` |
  | 这个对那个、之前对之后、错的对对的 | `Versus` |
  | 操作步骤 | `StepList`；检查项、注意事项用 `CheckList` |
  | 一个关键数字、价格、步数 | `BigNumber` |
  | 测速、跑分、排行 | `BarChart`；多方案多维度用 `Table` |
  | 流程、数据走向、架构 | `Flow`；事情经过、版本历史用 `Timeline` |
  | 一张截图或插画 | `ImageShow`（能推近、能圈出一块） |
  | 群友反馈、评论、多张真实截图 | `ShotWall`、`TextShot` |
  | 和 AI 对话、群里问答 | `ChatBox` |
  | 装软件、跑命令 | `Terminal` |
  | 「点这里、填这个、点确定」 | 电脑软件用 `AppWindow` 加光标和说明牌；手机 App 用 `Phone` |
  | 风险、坑、封号提醒 | `WarnCard` |
  | 吐槽、情绪点、反转 | `Meme`、`Stamp`、`SpeedLines`、`Burst` |
  | 全片回顾、片尾、制作说明 | `Recap`、`EndCard`、`MadeBy` |

  名字和参数以积木手册为准。
- **全屏级的冲击效果（集中线、盖大章、整屏变色）全片最多三处**，留给钩子、反转和结论。
- **换章先给标题。** 新一章开始后 0.15 秒内章节牌或标题就要出现，不留空舞台。
- **教操作的段落**：窗口占主体，光标走到哪、圈到哪、说明牌说什么，按「点哪里 → 填什么 → 看到什么算对」的顺序排。英文按钮旁边配中文说明牌。需要观众照着填的画面多停一会儿。
- 小咸鱼是气氛组：开场、吐槽、成功、收尾各出来一下就够，不要每屏都站着。同屏出现几个一样的角色时，隔一个左右翻转或换姿势。

## 二、场景文件的骨架

一章一个文件，放在 `film\src\scenes\`，再到 `scenes\index.ts` 按时间顺序登记。以示范片的场景为模板，结构都是这样：

```tsx
// 这一章的范围：本章开始前 0.35 秒 到 下一章开始后 0.35 秒（两章各淡 0.35 秒，自然交叠）
const range = () => [chapter('how').start - 0.35, chapter('prep').start + 0.35] as const;

const How: React.FC<{t: number}> = ({t}) => {
  const [a, b] = range();
  return (
    <div style={{position: 'absolute', inset: 0, opacity: edge(t, a, b)}}>
      {/* 章节牌：本章一开始就出来 */}
      {/* 第一段：从 h1 的 {direct} 到 h2 的 {gp} 之前 */}
      {/* 第二段：…… */}
    </div>
  );
};

// 这一章的音效：把用到的积木的音效函数展开进来
const sfx = (): Ev[] => [ ... ];

// demo：模拟界面出现的时段返回 1，角落会标「示意画面」
export const HowScene: Scene = {id: 'how', range, C: How, sfx, demo: (t) => (t > C('h1', 'direct') ? 1 : 0)};
```

要点：

- **时间只从这几个函数取**：`chapter('章id').start`（章开始）、`S('句id')`／`E('句id')`（句子起止）、`C('句id', '标记')`（标记时刻）。可以在它们上面加减零点几秒（出现略提前 0.05–0.1 秒，看起来更跟嘴），但不写 `t > 83.5` 这种绝对秒数。
- 最后一章的范围写到全片结束：`[chapter('end').start - 0.35, TOTAL()]`。
- 一章里有几段画面，就拆成几个小组件，各自管自己什么时候进、什么时候退（积木的 `t0`、`t1`）。**每个元素都要想清楚什么时候退场**，不写 `t1` 的东西会一直挂到这章结束。
- 相邻两段交接：前一段在后一段第一个标记前 0.3 秒左右退场。两段同时进退要错开至少 0.25 秒，不然搅成一团。
- 内容数据（卡片文字、步骤、表格行）写成文件顶部的常量数组，下面的布局代码遍历它。改内容不用动布局，画面文字也方便和稿子对。
- 所有动画都是 `t` 的纯函数。不用随机数、不用当前时间、不用 Remotion 的 `useCurrentFrame` 和 `interpolate`（片场的动画函数在 `lib\anim.ts`，积木内部已经用好了）。

## 三、版式的底线

积木的默认值已经守住这些，自己调位置、加文字时别破：

- **安全区**（横屏 1920×1080）：内容放在 x 110–1810、y 150–915 之间。y 940 以下是字幕条，绝不放东西；左上角（x 小于 700、y 小于 130）是章节牌。
- **字号档位**：整屏大标题 96–132；区块标题 64–76；卡片标题 40–46；正文 30–40，不小于 28；说明小字不小于 24。模拟界面内部的界面字可以小（真实软件就这么小），但关键位置用说明牌放大。一屏里字号不超过四档。
- **整屏的模拟窗口也要守安全区**：窗口的下边不能超过 y 930，否则会被字幕条压住（这是试片里真出过的问题：窗口下沿和输入框伸到了字幕条后面）。`ui\` 里旧片留下的界面件是按 1620×900 画的，直接用会超高：把整个窗口缩到 0.85 倍以内再摆，上边留给章节牌（窗口顶在 y 130 以下），或者这一章不放章节牌、章名交给换章过场。**镜头推近之后还要再算一遍**：画面上的窗口下沿 = 540 +（窗口下沿的舞台 y − 镜头中心 y）× 推近倍率，这个数不能超过 930；左右同理，推近后窗口边缘离画面边至少留 40 像素，别让窗口被切掉一条边。窗口越大能推的倍率越小（试片最后用的是窗口 0.78 倍、最多推到 1.2 倍）。`probe` 会提醒「模拟窗口压到字幕区」。
- **换章过场要留够时间**。`ChapterBreak` 的标题要能清楚停 1.2 秒以上，它的时长和章与章之间的配音留白（`film.json` 的 `pacing.chapterGap`、`leadLine`）是配套的：只加长过场会压到下一章第一句，只加大留白标题又读不完。照积木手册 ChapterBreak 一节的公式写，模板的默认留白已经按它配好，别改小。
- **缩放或移动了界面件，落点坐标要跟着换算**。`ui\` 里的界面件自带一批「某个按钮在哪」的坐标函数，是按窗口原始大小和位置给的。你把窗口缩小、挪位置之后，光标落点、圈选框、说明牌锚点都要经过同一个换算；写一个换算函数全片共用，不要有的地方换算、有的地方直接用原值。
- **光标和说明牌要落在说的那个按钮上**。念到「点删除」时，光标应当已经停在删除按钮上，说明牌指着它，按钮上的字不能被光标的点击波纹或说明牌盖住。抽帧时专门看一眼这几样是不是对着同一个东西。
- **一屏的量**：一块整屏积木 + 章节牌 + 至多两个小件（盖章、说明牌、小咸鱼）。卡片不超过 4 张，步骤不超过 6 步，表格不超过 5 列 6 行，流程节点不超过 5 个。超了拆成两屏，不缩小。
- **文字放在积木给的槽里**，由积木负责缩字号和换行。不要为了塞下更多字去改小字号下限；塞不下说明这屏内容太多，拆成两屏。
- **颜色各有含义**：珊瑚橙＝强调、当前这一步、警告；薄荷绿＝对的、完成；黄色＝划重点；墨蓝＝正文和描边。不用颜色表之外的颜色，不加渐变、发光、粒子。模拟某个产品界面时用那个产品自己的配色（手册里有）。
- **对齐和留白**：同一屏的元素左对齐或居中对齐，别东一个西一个；卡片四边内容留白不小于 26 像素；元素之间不小于 20 像素。
- 竖屏的安全区和字号见 [改片与短版.md](改片与短版.md)。

## 四、积木不够用的时候

先确认是不是真的不够：翻一遍手册总表，很多画面换个思路就能用现成积木拼（「想画一张架构图」→ 流程图积木；「想展示一段配置」→ 终端窗或软件窗口）。

确实没有的：

1. 用积木库里的小件（贴纸白卡、标签、箭头、自适应文字）在场景文件里拼一个，样子向最接近的积木看齐：5 像素墨线描边、圆角、硬投影、弹簧出场。
2. 要模拟一个积木库里没有的软件界面：用通用软件窗口积木搭框架，里面的内容照真实截图排，文字照源码或截图写，配色取那个软件自己的主色。旧片里已经做过的界面（Claude 网页、Codex 桌面版、FAswitch、安卓手机）在 `film\src\ui\` 里，可以直接用；它们怎么用，可以去读旧片的场景（本频道的旧片工程，如 `<工作区>\work\FAswitch上手流程\film\src\scenes\`、`Claude入门教程`、`GooglePlay订阅AI`；开源版不带这些工程）。旧片工程是片场之前的做法，没有 `film.json`、`film.cmd` 和制作记录，目录结构和现在不一样，只读它的场景写法，不要照它的流程做，也不要在里面跑命令。
3. 做完比平时更仔细地抽帧看，并在交付报告里写明「这一处是自己拼的」，方便上级重点看。

不要做的：自己另起一套视觉风格；用代码画人物、动物、复杂插画（交给画师）；从网上找图标图片塞进来（版权和风格都对不上，图标用 `ui\icons.tsx` 里现成的）。

## 五、写完一章就看一章

```
.\film.cmd lint                              # 稿子体检 + 类型检查，先清零
.\film.cmd probe zh --round w1 --only how    # 机器量版面
.\film.cmd review zh --round w1 --only how   # 抽这一章的帧
```

逐张看图的方法和清单在 [验收.md](验收.md)。常见的第一眼问题：东西挤在一边、文字出框、元素压元素、换章后空舞台、该退场的没退。当场改掉再写下一章，比全片写完一起返工省事得多。
