# 读懂产品，写产品简报

动手之前先弄清四件事：产品说自己是什么（官网原话）、它真实长什么样（界面）、哪些状态拿得出来展示、哪些信息不能露。四件事写成一页「产品简报」，记进 `制作记录.md`。后面的文案、分镜、截图全部从这一页取，简报里没有的东西不进片子。

这一步只读、不改。产品的仓库、官网、安装包一个字节都不动；要跑产品的前端就拷一份副本到自己的工程里跑。

## 一、事实从哪来，按这个次序

1. **派单和创作简报。** 用户原话是最高依据。
2. **产品官网首页，整页读完。** 文案只从这里取（见[文案](文案.md)）。官网怎么说自己，片子就怎么说，不替产品发明卖点。
3. **产品当前版本的界面**：源码里的界面文字，或者把它跑起来看到的真实界面。字段名、按钮名、状态名照它写。先确认是哪个版本。
4. **[频道规矩](../频道规矩.md)。** 用词的边界在那里（不说防封、躲风控、指纹浏览器；节点的讲法；不承诺效果）。

不算数的来源：你对这类产品的印象、别的产品的说法、旧版本的截图、你觉得「它应该有」的功能。

## 二、卖点表

把官网上讲产品能力的句子原样抄下来，一句一行，填这张表：

| 官网原话 | 出处（文件和行号，或网址和所在区块） | 界面上哪里能给它作证 | 用不用 |
|---|---|---|---|

「界面上哪里能给它作证」是这张表的关键一列。产品片的规矩是每句话都要有画面作证（[审美判例](审美判例.md) 主2），一句话在界面上找不到任何对应的东西，它就进不了片子。

FAswitch 的卖点表（范例，出处是官网首页源码）：

| 官网原话 | 出处 | 界面上哪里作证 | 用不用 |
|---|---|---|---|
| 账号、代理、时区，各归各位。 | 标题和首屏大字 | （全片的总括） | 用，落款标语 |
| FAswitch 在你自己的电脑上运行。 | 首屏导语 | 五个页面的全貌 | 用 |
| GPT 和 Claude 账号放进档案里各自登录，切换时互不串号。 | 首屏导语 | 账号页：GPT 和 Claude 两组账号卡 | 用 |
| 档案绑定一个代理出口和时区。 | 「档案与账号」卡 | 代理接入页：档案名、节点两个输入框 | 用，主陈述从这句来 |
| 切换后检测环境一致性和 IP 质量，每 6 小时自动复查，时区和语言按出口对齐。 | 「环境自检」卡 | 顶栏的四枚环境标签（出口、时区、一致性、IP 质量） | 用 |
| 代理只给档案启动的程序用，不改系统代理。 | 「环境自检」卡 | （没有单独的界面元素，配在全貌镜头上） | 用，当副句 |
| 本机记录每个账号的请求、token 和额度走势，按官方 API 价格折算。 | 「用量统计」卡 | 用量页的四枚指标卡和曲线 | 用 |
| 免费使用 · 源码不公开 · 禁止倒卖 | 首屏小字、页脚 | （落款小字只取「免费使用」） | 用一半 |

抄的时候一个字都不改。改写放到文案那一步做，而且改写后的每一句都要能指回这张表里的某一行。

## 三、界面盘点：哪些状态拿得出来

把产品跑起来（或读源码），列出每个页面、每个页面里值得拍的状态：

| 页面 | 状态 | 这个状态里最能说明问题的东西 | 适合当主角吗 |
|---|---|---|---|
| 账号页 | 两组账号都有卡片，其中一张「运行中」 | 账号卡：名字、邮箱、档位、额度条 | 适合，开场主角 |
| 代理接入页 | 档案名已填、节点已选 | 两个输入框和「绑定并建档」按钮 | 适合 |
| 顶栏 | 四枚环境标签都是通过状态 | 「一致性 100」「IP 92 · 住宅 · 原生」 | 适合 |
| 用量页 | 有一段时间的数据 | 四枚指标卡、曲线 | 适合 |
| （反面的样子）某个只有一排开关的设置页 | 默认 | 没有 | 不适合，没有能作证的东西 |

挑主角状态时问三个问题：

- 这个状态里有没有**具体的字或数字**能让人一眼看懂产品在干什么？（「一致性 100」有；一排灰色开关没有。）
- 这块界面放大到半个屏幕，还好不好看、内容满不满？（空列表、加载中、只有一行字的页面不行。）
- 它对得上卖点表里的哪一行？对不上的不拍。

空状态、报错状态、加载骨架条不当主角。教程试片里真出过这种事：设置页右栏整片是灰色骨架条，审片员的意见是「第一眼像没加载完」。

**功能要一项一项对上镜头。** 把卖点表里标了「用」的每一行，对到一个页面状态上，就是分镜的底稿。一项能力没有对应的镜头，观众就不知道它有；两个镜头对着同一项能力，删一个。

## 四、截真实界面

产品片里的界面必须是产品真实的前端代码渲出来的，不用代码照着画一份（[审美判例](审美判例.md) 主4）。这一步最费工，也是质量的地基。

用镜头包的截图工具：写一份截图清单（哪个页面、截之前点什么填什么、哪些元素要记坐标、哪些要藏掉另截底板、哪些要单独抠图、从哪取色），一条命令截完。清单的格式、命令、演示数据脚本能用的小工具（造假后端、拦接口、把时间钉住）都在手册「截界面」一节，范例片的清单可以照抄。做法的要点：

- 把产品的前端拷一份只读副本到工程里，给它接一个假后端，假后端只返回演示数据。
- 整页按 3 倍像素密度截（不低于 2 倍），等内容加载完再截。镜头推近以后字还得是清楚的，这要靠截图本身够大；推得比截图倍率还近时，抽帧会提醒。
- 视口宽度按内容的实际宽度收。视口太宽，截出来左边是内容、右边是空的，放进三维里很难看（做第三版时从 1440 收到了 1240）。工具会在核对清单里标出「视口比内容宽太多」。
- 一个要做动画的页面，工具一次出四样：整页的图；把要动的元素藏起来之后的底板；要动的元素各自的透明底抠图；坐标表（每个元素的位置、文字、字体、颜色，外加从界面取的色板）。元素要「落回槽位」、要打字、数字要滚动，都要一张把它们藏掉的底板。所以**先想清楚每个镜头里谁要动，再写清单**；动作改了，清单要跟着改、重截。
- 坐标表里的位置是截图那一刻相对窗口可见区域量的，跟着滚动位置变。同一页要多截一个滚动位置，把滚动写进那一页的步骤里，不要截完再自己加减。
- 只重截其中一页时，工具会把「截图核对清单」整份重写成只有这一页。要留一份全量的核对记录，就整份清单重截一遍。
- 要演「切换前后」「筛选前后」这类状态变化的，前后两个状态都要截。
- 全量截图放在分镜定了之后。分镜没定就全截，状态一改全部重来。出风格帧之前先截要用的那几张就够。

**演示数据**用[频道规矩](../频道规矩.md)那一套：邮箱 `yourname@gmail.com`、档案名「日常工作」、节点「美国 · 洛杉矶 01」。需要第二、第三个账号时顺着编（`yourname2@gmail.com`），网址用 `api.example.com` 这种示例域名。数字（额度、用量、评分）编得像真的：不要全是 100%、不要 12345 这种一看就是假的数。

截图工具会顺手写一份「截图核对清单」：每一页全部可见的文字，加上它自动标出的可疑内容（IP、端口、清单里没允许的邮箱、网址、密钥样式、你列的禁用词），以及演示后端里没接上的方法。先读这份清单，把允许出现的演示邮箱和禁用词在截图清单里写好。但工具只标得出最常见的几类，所以：

**截完必须逐张原尺寸看一遍，对着下面这张表打勾**，不能只看工具的清单，更不能只检查假后端的数据文件。真实的教训：做第三版时，截出来的图里下拉框选项带出了第三方代理软件的名字，另一处直接写着那个软件的全名。这种东西只看数据文件发现不了，要看图。第三版最后逐张核过六个页面，把软件名换成了「本机代理」，带端口的那个页面干脆没用。

| 逐张核对 | |
|---|---|
| 有没有真实的邮箱、姓名、昵称、头像、手机号 | |
| 有没有 IP、端口、订阅地址、密钥、本机用户名、本机路径 | |
| 有没有第三方软件、第三方服务商的名字或图标（换成中性的说法，如「本机代理」） | |
| 演示数据是不是规定的那一套 | |
| 有没有「加载中」、空白下拉框、「请选择」、报错提示这类没填好的状态（范例片的一页上留了一行「…操作没有返回状态」，是演示后端有个方法没接；它只出现在最远的一页上读不出来，记进了已知瑕疵。主角页面上不能有这种东西） | |
| 字体、图标、图片都加载出来了吗（有没有方块字、裂图） | |
| 版本号、价格、日期：派单没让露的有没有露 | |

异步回填的地方（下拉框显示「选择档案」）不用把整套接口都仿全，截图前直接把那处的文字改对就行。

「示意画面」角标：被认可的那组风格帧里没有放，用户认可了。要不要加由派单定，派单没写就不加。

## 五、从产品自己身上取颜色和字

片子的底色、强调色、字体、圆角，从产品界面的样式里取，记进简报。取色写在截图清单里（读界面的样式变量或某个元素的颜色），截完坐标表里就带着色板，镜头包用它生成全片的主题。组件里没有让你填颜色的地方，这是有意的：不另起一套「宣传片皮肤」。

| 要取的 | 从哪取 | FAswitch 的例子 |
|---|---|---|
| 底色 | 界面的背景色 | 石墨黑（界面暗色主题的底） |
| 强调色 | 界面里表示「正常、选中、进行中」的那个颜色 | 森绿 |
| 第二个功能色（可没有） | 界面里另一个有含义的颜色 | 信息蓝，只给「机器在检查」的扫描线和标注用 |
| 亮场的颜色（深色界面才需要） | 应用图标或官网的底色；没有就用镜头包默认的暖白 | 图标的米白，全片只用一次 |
| 界面里的字 | 就是截图里的字，不动 | — |
| 大字陈述的字体 | 镜头包里锁死的：中文思源黑体 800 字重，拉丁字母和数字用 Inter，小标用等宽字体 | — |
| 徽标 | 原图文件，不照着重画 | 应用图标原图 |

界面是浅色的产品，舞台和明暗的安排和范例相反，见[审美判例](审美判例.md)画10。

取色只是第一步。被否的那一版也取了官网的纸色和森绿，可画面里的东西（曲线、月亮）产品里没有。颜色从产品来，画面里的东西也得是产品里的东西。

## 六、「这条片子证明什么」

简报的最后一行，写一句话：

> 这条片子证明：**（产品）让（谁）能（做到什么）**。证据是界面上的（哪几样真实的东西）。

FAswitch 的：

> 这条片子证明：FAswitch 让同时用 GPT 和 Claude 的人，把每个账号的登录、出口和时区固定在一份档案里。证据是账号页的两组账号卡、代理接入页的档案名和节点、顶栏的四枚环境标签、用量页的数字。

写不出「证据是…」那半句，说明还没读懂产品，回到第二、三节。写出来的这句话不进画面，它是用来检查每个镜头的：一个镜头不在为这句话提供证据，就不该在片子里。

## 七、简报交上去之前自查

1. 卖点表里每一行都是官网原话吗？出处写了吗？
2. 标了「用」的每一行，都对上了一个页面状态吗？
3. 主角状态里有具体的字或数字吗？有没有拿空页面、骨架条当主角？
4. 不能露的信息列了吗？派单和频道规矩里的用词边界抄过来了吗？
5. 版本确认了吗？界面文字是从这个版本取的吗？
6. 「这条片子证明什么」里的每个证据，界面上真的有吗？

## 你最容易在这一步出的错

- **替产品编卖点。** 官网没说「更安全」，你觉得它应该更安全，就写了。教程试片里，一位 DeepSeek 审片员建议加一句「反代等于把账号交到别人手里」，材料里没有出处，剪辑师没有采纳，做对了。
- **只查数据文件，不看截出来的图。** 见第四节那个第三方软件名的例子。
- **把所有页面都拍一遍。** 产品有十个页面不等于片子要十个镜头。只拍能给「这条片子证明什么」作证的。
- **照着截图用代码重画一份界面。** 这是教程片的做法，产品片不行。
