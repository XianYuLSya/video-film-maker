# 产品片总纲（品牌片、发布片、宣传片都走这一套）

**一句话标准：看完的人觉得，这是一个强大、精密、可信的专业工具。**

产品片是 30–45 秒、基本不说话的片子：产品的真实界面放在三维空间里，镜头贴近、掠过、推拉；每个镜头配一句粗重的大字陈述；剪辑踩着音乐的拍子；徽标只在结尾落款。它不教人怎么用，它让人相信这个东西值得用。

这一份是总纲：这类片子和教程片差在哪、两版真实的对照、全流程每一步的过关条件、哪里必须停下来等人拍板。先把它读完，再按第十节的顺序读其余几份。

## 一、什么时候走这一套

派单的类型写的是品牌片、产品片、发布片、宣传片、品牌动画、logo 演绎、发布片头，都走这一套。只要一个几秒钟的徽标落款，也从这里取（只做[分镜](分镜.md)里「落款」那一段）。

派单写的是教程、介绍、对比测评、整活，不走这一套，回 `SKILL.md` 的主流程。一部教程片的片尾想要一张品牌卡，那一幕按这里的落款做，其余照旧。

## 二、和教程片的根本区别

教程片你已经会做了。产品片的每一条都和它反着来，照教程片的习惯做，一定做坏。

| | 教程片 | 产品片 |
|---|---|---|
| 目的 | 教会观众做成一件事 | 让观众相信这个产品强大、精密、可信 |
| 谁在说话 | 口播从头讲到尾 | 基本无口播；说话的是画面和大字 |
| 画面主角 | 积木：卡片、流程图、清单、吉祥物 | **产品的真实界面**，没有吉祥物 |
| 界面从哪来 | 代码画的模拟界面，标「示意画面」 | 用产品真实的前端代码配演示数据**截出来**的界面 |
| 底和质感 | 奶油纸底、粗描边白卡、硬投影 | 从产品自己的界面取色；三维空间、景深、一盏主光 |
| 字 | 标题字体、字幕条 | 每镜头最多一句粗重大字（800 字重，88 像素起），没有字幕条 |
| 运动 | 弹簧弹出，热闹 | 不弹；快起慢停；镜头稳 |
| 时间从哪取 | 口播的句子和标记 | 音乐的拍子（垫片起点 + 拍数 × 拍长） |
| 工具 | `blocks\` 积木库 | `cine\` 产品片镜头包（手册在同目录 `手册.md`） |
| 一屏的量 | 一个主视觉加最多三个附属 | 一个主角；其余的东西可以在，但要虚、要暗、要退后 |

对照图：`参照图\对照_教程片长这样.jpg`（教程片）和 `参照图\正例_总览.jpg`（产品片）。

2026-11-11 用户看了一版照教程片风格做的品牌画面，原话：「要做高端来，前面的都太低级，太普通，太儿戏化了，真正的品牌，你看看人家头部大厂的都是咋做的」。

## 三、被否的一版和被认可的一版

这一节是整套教材的核心。同一个产品（FAswitch）、同一天、同一句标语，前后做了三轮：第一轮照教程片风格，被否（原话见上）；第二轮整片做完，又被否；第三轮先出风格帧，方向被认可。下文把第二轮叫「被否的那一版」，第三轮叫「第三版」。

把两张图并排打开，对着下面的表看：`参照图\反例_全片连看.jpg` 和 `参照图\认可版_全片连看.jpg`。

**被否的那一版**（19 秒）：深色夜底，三条曲线缠在一起，理顺成「账号、代理、时区」三行字；一轮暗月升起，手绘的睡鱼在月亮前一笔描出来；月亮扩成一页纸，落成徽标和标语。配色克制、字细、留白多、动作不弹、对着拍子，调研里列的廉价感来源它基本都避开了。DeepSeek 剪辑师照设计稿做得逐像素一致，自评 8.5 分。

用户（2026-11-11）：「方向正确，有那个味，但是还很肤浅」；紧接着：「就是依旧太儿戏了，假如人家大厂的品牌视频是商业精英，你这个就是幼稚园水平」「或者小学生水平」。

**第三版**（8 张风格帧）：每个镜头都是 FAswitch 当前版本的真实界面，放在三维空间里带景深地拍；每镜头一句粗重的中文陈述；主陈述「一个档案，一个出口」是全片唯一的亮场；睡鱼只在最后几秒当落款。

用户看了风格帧（2026-11-11）：「对」。

第三版的整片后来做完了，40.7 秒。用户看了整片（2026-11-11）：「那个整片我看着效果挺不错的，有那味了，对了」。所以第三版的风格帧和整片都是被认可的。要记住的是顺序：先有被认可的风格帧，才有被认可的整片。

**范例片。** 第三版是另一位设计师借助第三方库做的。之后我们用自己的镜头包（`cine\`）和片场流水线，按同样的分镜、拍号、文案把它重做了一遍，顺手改掉了第三版自己列的几处瑕疵和偏暗，这一条叫「范例片」。它是你照着手册能做出来的东西，工程可以照抄。范例片和第三版并排看水准一致、整体更亮（`参照图\认可版对范例_关键时刻并排.jpg`，左边是用户认可的，右边是范例片）；写这份教材时用户还没有对范例片表态。

参照图的名字由此分三种：`反例_…` 是被否的那一版；`认可版_…` 是用户看过并认可的第三版原片；`正例_…` 是范例片。

| | 被否的那一版 | 第三版 |
|---|---|---|
| 主角 | 图形和比喻：曲线、月亮、睡鱼。观众记住的是一条可爱的鱼 | 产品本身：8 张风格帧里 7 张是真实界面，1 张是落款（`参照图\认可版_风格帧总览.jpg`） |
| 说了什么 | 三个词各配一根线、一个标签。没有一句完整的话，没有任何证据 | 每镜头一句具体的陈述，每句都有界面上真实存在的东西作证（「一致性 100」「美国 · 洛杉矶 01」「$441.07」） |
| 全片的高点给了谁 | 给了睡鱼在月亮前被描出来 | 给了一句产品陈述：「一个档案，一个出口」 |
| 空间 | 平面上淡入淡出 | 三维空间里的面板，镜头贴面掠过、侧面斜看、推近，带景深 |
| 字 | 76 像素、300 字重的细字 | 88–104 像素、800–900 字重；主陈述 300 像素 |
| 密度 | 19 秒里发生 5 件事，件与件之间是等待 | 40 秒 7 个镜头，音乐进满能量的那一拍正好是主陈述 |
| 动作 | 线在理顺、鱼在被描，演的是比喻 | 产品自己的元素在演：卡片里的字落回槽位（各归各位）、一组账号卡飘走另一组嵌进来（互不串号）、扫描线逐个框住环境标签（体检） |
| 可爱的东西 | 是主戏 | 只是落款，而且删掉了让它「晃两下」的预备动作 |

逐项的并排图：`参照图\并排_同一件事.jpg`、`并排_全片高点.jpg`、`并排_落款.jpg`。

一句话：**被否的在演一个可爱的东西，第三版在证明一个精密的工具。**

这件事对你最要紧的教训有三条：

1. **不犯错不等于做得好。** 被否的那一版，版面体检零错误，和设计稿逐像素一致，做它的 DeepSeek 给自己打了 8.5 分。它的问题不在任何一帧的细节上，在路子上：画面里没有产品。所以这类片子的方向必须由人看过风格帧再定，你的自评分只决定「能不能交上去」。
2. **克制是手段，不是目的。** 「元素少、留白多、字细、颜色淡」这些只负责不廉价，负责不了有分量。分量来自产品本身：真实的界面、真实的字段、真实的功能。
3. **「少」指的是焦点少，不是内容少。** 第三版的画面里东西很多（一整页真实界面），但每一刻只有一处是清楚、明亮的，其余靠景深和压暗退到后面。被否的画面把东西删到只剩三行字，观众没东西可看。

两个随时可以对着图做的检验（老师归纳的办法，后面的评审表里会用到）：

- **遮名检验**：把徽标和产品名遮住，随便停一帧，观众说得出这个产品是干什么的吗？被否的那版任何一帧都说不出。
- **换名检验**：把产品名换成另一个产品，这一帧还成立吗？曲线、月亮、光斑换给谁都成立，说明这一帧和产品没关系。

## 四、全流程

顺序不能换。每一步的产物都写进工程的 `制作记录.md`，过关条件不满足不进下一步。

| 步 | 做什么 | 读哪份 | 过关条件 | 谁定 |
|---|---|---|---|---|
| 0 | 读派单、频道规矩、本目录全部文档、`cine\手册.md`；把参照图看一遍 | 本文、[审美判例](审美判例.md) | 能说出两版差在哪 | 你 |
| 1 | 读懂产品，写产品简报 | [产品简报](产品简报.md) | 卖点表每条有官网原话和出处；列出可展示的界面状态和不能露的信息；写出「这条片子证明什么」 | 你写，上级看 |
| 2 | 写文案：主陈述和每个镜头的一句话 | [文案](文案.md) | 文案自查全过；每句有出处。主陈述派单已给就用派单的，没给就出三条候选并写明你推荐哪条 | 主陈述由上级定 |
| 3 | 选曲、量拍、选结构骨架、写分镜表 | [分镜](分镜.md) | 拍长和「进满能量」的拍号量出来了；分镜表每个镜头写清：证明什么、主角是哪块界面、动作演的是什么、拍号、大字 | 你定，曲子的气质上级听 |
| 4 | 截真实界面 | [产品简报](产品简报.md)第四节、`cine\手册.md` | 每张截图逐张核过演示数据；推近后字是清楚的 | 你 |
| 5 | 出风格帧，自评，**停下来交上级** | [风格帧](风格帧.md) | 上级明确回复「通过」。没有这句话不许往下做 | **上级和用户** |
| 6 | 做整片：给每个镜头补运动、接转场 | [分镜](分镜.md)、`cine\手册.md`、[审片](审片.md) | 每个镜头连续抽帧看过，问题关闭 | 你 |
| 7 | 声音：音效钉在拍上、混音 | [分镜](分镜.md)第七节、[声音](../声音.md) | 画面时间线已经不再动；音效表每条对着一个画面动作 | 你，听感交人 |
| 8 | 全片自审，写判例自检报告，交审片节点 | [审片](审片.md)、[审美判例](审美判例.md) | 审片记录里没有未关闭的问题；独立审片意见逐条处理完 | 你和审片员 |
| 9 | 渲染、合成、成片体检、交付 | [验收](../验收.md)「成片体检」、[审片](审片.md)第五节 | 体检表全过；**从成片里抽帧看过**（不是只看审片阶段的帧）；「未验证」写明 | 上级验收 |

片场命令和教程片是同一套（`.\film.cmd …`）。产品片不同的地方有这几处，细节在片场 README「产品片」一节和 `cine\手册.md`「一条 30–45 秒的产品片怎么搭」：

- **开工程**用 `new_film.py <作品名> --kind product`。建出来是一部能直接跑的三镜头起步工程，配置、稿子、场景、制作记录都已经是产品片的写法，在它上面改。
- **稿子全是垫片**，一个镜头一个，写它占几拍（`"beats": 10`）。整片一句口播都没有也能跑完全流程（实测过）；`voice` 这一步照样要跑，它负责把时间表和拍子网格算出来。
- **`film.json` 里要有拍子网格 `music.grid`**，场景里的时刻一律写 `B(拍号)`。片场内置的三首曲子可以直接当网格用。
- 场景整屏自管（`bare: true`）。
- **改了画面再渲，`render` 必须加 `--fresh`**（或用 `--from --to` 只重渲改过的几秒）。不加的话，已经渲好的分段会被跳过，成片里还是旧画面，体检照样全绿。渲完从成片里抽帧再看一遍（[审片](审片.md)第五节）。
- 镜头包的防呆提醒（`[注意] [镜头包] …`）只在抽帧时打印，整片渲染时不打。所以先抽帧、看提醒、改完，再渲。
- 派单要无配乐版时，`film.json` 里开 `alsoNoMusic`，会多出一条只有音效的成片。

## 五、哪里可以一路做下去，哪里必须停

你可以自己走完的：读产品、写简报、写文案候选、量拍、排分镜、截界面、出风格帧、做运动、对拍、混音、自审。这些事有清单、有工具、有数字可核。

**必须停下来等回复的只有一处：风格帧（第 5 步）。** 用 `ask_parent` 交上去，等到明确的「通过」再做整片。原因是三条真实的教训：

- 这条片子两轮返工，全是方向错。第二轮是整片做完才给用户看的，整片白做。
- 做第三版的设计师复盘：片子大约七成的质量在风格帧阶段定下来，错的方向在静帧上一眼就能看出来，返工成本只有成片的十分之一。
- 方向对不对，你自己判断不了。上面那个 8.5 分就是证据。

风格帧节点一次交三样，让上级一次定完：主陈述和全片文案、8 张左右的风格帧、你的自评表（再加曲子的试听片段）。等回复期间可以做不依赖答复的事（核截图、写音效表的骨架），不要开始做运动。

另外两个节点照教程片的做法，交完继续做，不用等：

- 全片自审完、整片渲染之前：交审片记录和判例自检报告，上级会派独立审片员。
- 成片：按 `SKILL.md` 的交付报告格式，再加[审片](审片.md)末尾要求的几段。

其余什么时候用 `ask_parent`，照 `SKILL.md`「什么时候停下来问」。产品片多一条：**想不出某个功能怎么「演成动作」，或者风格帧被退回两次还不过，停下来请上级升级**（见[派单](派单.md)），不要硬凑。

## 六、范例片：什么可以换，什么不能动

范例是 FAswitch 的片子（范例片的工程，位置见文末「本机参照物」；`film\src\shots\` 一个镜头一个文件）。镜头怎么写可以照抄它；照着它做别的产品时，你最容易把它的皮也一起抄走。

| | 说明 |
|---|---|
| **必须换** | 界面（截你这个产品的）；配色、字体、圆角（从你这个产品的界面取）；每一句文案；主陈述；每个镜头「动作演的是什么」；小标的英文；徽标和落款文字 |
| **看情况换** | 镜头数量和顺序（按这个产品有几项能证明的能力）；曲子；亮场放在哪；哪个镜头用哪种机位 |
| **不能动** | 流程和过关条件；主角是真实界面；一个镜头最多一句话、只有一个主角；全片只有一句顶点；全屏级冲击不超过三处；落款才出徽标；`cine\手册.md` 里标了「锁死」的参数；风格帧必须过人 |

石墨黑底配森绿，是因为 FAswitch 的界面就是这个颜色。你的产品界面是白底蓝色，片子里的界面就该是白底蓝色；这时舞台和明暗的安排也要跟着反过来（浅色界面配暗场，主陈述不再翻成亮场，见[审美判例](审美判例.md)画10）。镜头包的陈列片整部用的是一个浅色的示例界面，可以看它。「一个档案，一个出口」这个句式也不是模板，别把别的产品硬套成「一个 X，一个 Y」。

## 七、制作记录里要多记的

用 `--kind product` 开的工程，`制作记录.md` 已经带了产品片的小节，照着填，一节都不要删：

- **产品简报**：卖点表、可展示状态表、不能露的信息、「这条片子证明什么」。
- **文案**：主陈述、每镜头一句、每句的出处。
- **节拍数据**：曲子、拍长、第一拍在哪、能量结构（第几拍进满、第几拍回落）、数是怎么量的。
- **分镜表**（按拍号）。
- **取帧表**：每一轮审片照着取的秒数（落定帧、主动作、接缝），见[审片](审片.md)第一节。
- **风格帧评审**：自评表、上级的回复原文、改了什么。
- **审片记录**：每轮的体检结果、亮度、问题表、数数表。
- **判例自检报告**：按[审美判例](审美判例.md)的编号逐条写「过」或「不过（哪个镜头、哪一帧）」。
- **有意不照判例做的地方**：哪一条、为什么、谁同意的。判例可以破，但要上级同意，并且写在这里。

## 八、工具和素材

- **片场**：一条命令驱动的流水线，命令和配置以片场的 `README.md` 为准。位置看 `SKILL.md`「片场」一节。
- **产品片镜头包**：片场模板里的 `film\src\cine\`，每部新片会带一份。镜头的名字、参数、写法、截界面的工具、按拍取时间的办法、审片工具、防呆清单，全部以它的 `手册.md` 为准。这份教材里出现的组件名和命令是写作时从手册抄来的，方便你对上号；两边不一致时，镜头的名字、参数、能力听手册的，流程和过关条件听这份教材，并在报告里提一句。
- **看效果**：镜头包的陈列片（每种镜头几秒，用一个虚构的浅色界面演示）和范例片。手册每张镜头卡上写了它们的秒数。
- **参照图**：本目录 `参照图\`，教材自带。用看图工具打开时，拼成「这份 skill 的目录 + `references\产品片\参照图\` + 文件名」。
- **配乐和音效文件不随这份 skill 提供。** 教材里讲的是方法和声音的类别；手上有哪些曲子和音效、放在哪，看片场 README。
- 别的作品目录和片场一律只读。

## 九、这份教材里的话有几种成色

写的时候分了三种，引用时别混：

- **我们自己验证过的**：有用户原话，有被否或被认可的图。[审美判例](审美判例.md)里每条都标了。
- **第三版设计师的做法和判断**：来自它的做法复盘和自检报告。风格帧的方向和整片用户都认可了。
- **范例片的经过**：用自研镜头包重做时真实踩到的问题和改法，来自范例片的制作记录和手册。范例片和被认可的那条并排水准一致，用户尚未表态。
- **调研来的、第三方库的经验**：有出处，但我们自己的片子还没验证过。单独列在[审美判例](审美判例.md)最后一节。

评审表的分数线、几种还没用过的结构骨架，都是初定的，等真实的片子做过再改。
