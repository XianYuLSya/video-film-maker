# 写稿

口播稿 `film/src/script.json` 是全片唯一的正文：配音、字幕、时间表都从它生成，画面按它里面的 `{标记}` 对点。稿子没定就不要写画面。

## 一、先取材，再动笔

稿子里的每个事实都要有出处。动笔前把材料备齐，填 `制作记录.md` 的「事实表」一节：每条写「说什么 ｜ 出处（文件路径和行号、链接或派单原话）」。查不到出处、因此不写进稿子也不能在画面上暗示的东西，记进「未验证」一节。

- **派单给的材料**先读完：创作简报、调研结论、用户原话、指定的源码或文档。
- **讲某个软件怎么用**：以该版本的源码、安装包里的界面文字或真实截图为准，按钮名、菜单名、提示语原样抄。先确认讲的是哪个版本，不同版本界面和行为会不一样。
- **重做别人的片子或录屏**：先把原片看懂，方法见 [素材.md](素材.md)「看懂一条现成的视频」。原片的声音和画面都不直接用，只当素材来源，按本频道的讲法重排。
- **拿数据说话的片子**（对比、测评）：数字从原始记录里抄，同一个数字在稿子、图表、结论里出现几次就核几次，必须一致。
- 查不到、核不实的：不写进稿子；确实要提的，口播里说成个人经验，并在交付报告里列进「未验证」。

**内容判断比技术更容易错。** 技术错误会报错，知识点错了不会。真实案例：一部讲国内卡订阅的片子，写稿时为了不教「换区」，把「付款时网络出口要和账单地址在同一地区」也一起删了，还改成「付款时把代理关掉」。对出门在外的观众这是错的，照做付不了款，被用户当场纠正后改稿、改画面、重渲。删一个知识点之前，想清楚它拦的是什么、会不会把该教的也拦掉；拿不准就在交付节点提出来。

## 二、结构

先写提纲（章节和每章要兑现的承诺），再写句子。提纲写进 `script.json` 的 `chapters` 和 `制作记录.md`。

**教程类**（教人做成一件事）：

1. 开场（前 20 秒）：观众的问题 → 证据或结果 → 这期讲几件事。
2. 为什么这样做能成（一两句原理，讲成人话）。
3. 要准备什么。
4. 一步一步操作（每步：点哪里、填什么、看到什么算对）。
5. 常见卡点和处理。
6. 回顾（全流程收成一屏）。
7. 收尾：答疑去哪、署名。

**介绍类**（介绍一个工具或项目）：

1. 开场：一句话说它能干什么，最好直接演示结果。
2. 它和观众已经知道的东西差在哪（观众第一反应是「这不就是 xx 吗」，主动回答）。
3. 怎么用（一次完整演示）。
4. 真实案例（最好用真实数据）。
5. 怎么装、要什么条件。
6. 常见问题和限制（照实说）。
7. 收尾。

**对比测评类**：开场直接剧透最反直觉的结论 → 规矩（怎么比的、公平性）→ 一轮一轮比（每轮：题目、结果、一句判词）→ 总排名 → 怎么选 → 收尾。

**时长**：正片跟着内容走，常见 5–8 分钟；竖屏短版 43–60 秒。

## 三、开场怎么写

前三句决定观众留不留。写法是「问题 → 证据 → 这期讲什么」：

```
c1 「B 站这张{card}2233 联名万事达卡，{q}到底能不能订 Claude Pro？」
c2 「我朋友 {fr}小林 实测：在{phone}安卓手机上通过 {gp}Google Play，{cl}Claude Pro 和 {gpt}ChatGPT Plus {ok}都订上了。」
c3 「可很多教程讲到付款，就剩一句{only}「按提示操作」。」
c4 「这期就{btn}一个按钮一个按钮讲清楚，{p1}绑卡被拒、{p2}「已冻结」短信、{p3}IP 要对上地址，{all}这些坑也一起讲到。」
```

另一个范例（先点痛点，再交代本期两部分）：

```
「Claude 怕封号，GPT 怕降智？已经降智了，又该怎么恢复？」
「这期讲两件事：先用 FAswitch 固定使用环境，一张图，五步带你上手。」
「再按我的使用经验，讲 GPT 降智后的处理和恢复：旧对话怎么清，账号怎么养，每天怎么测。」
```

介绍类可以直接用结果开场：

```
「{say}在 Claude 里说一句话，{four}四条大肥鱼同时开工，{back}做完，报告自己交回聊天。」
```

不要这样开场：先放片头再说话；先自我介绍；先讲背景历史；先放「制作说明」。开场说过「这期讲两件事」，后面换到第二件时要呼应一句（「接下来，讲开头说的第二部分」）。

## 四、句子怎么写

- **口语，短句。** 一句话一个意思，念出来 3–8 秒。去掉标记后超过 60 个汉字就拆开。晓伊每分钟大约念 270–290 个字，可以据此估时长。
- **讲操作讲成人话**：「照着卡填：卡号、有效期，还有卡背面的三位安全码。」
- **预判观众的情绪**：「银行短信写着「已冻结」，别慌：这是先冻结、后入账，最后扣多少，看银行账单。」
- **把最常见的错写成一句提醒**：「先去 Play 里看订阅状态，别因为看到冻结就再付一次。」
- **照实说限制，但不削弱主线**：「能不能付成，以 Google Play 页面为准；被拒了别反复重试，换张卡，或者问问银行。」
- **一句话讲清原理**：「在官网订，是网站直接从你的卡上扣钱，收不收这张卡，它说了算。」
- **三句话收全流程**：「所以只要三步：把卡绑到 Google Play，在 App 里点订阅，以后在 Google Play 里管理。」
- **收尾引流不喊福利**：「付款卡住了，先看置顶评论；还不行，带着截图来 QQ 群问，群号在简介里。」
- 数字、英文缩写、型号写原样（字幕要显示），念法另外写进 `film.json` 的念法表，见 [声音.md](声音.md)。

## 五、`{标记}`：画面对点的锚

标记写在「画面要在这一刻发生点什么」的那个词**前面**。配音时标记被去掉，它所在位置的那个词开始念的时刻，就是画面里 `C('句id','标记')` 取到的秒数。

- 标记名写「这一下发生什么」，用英文小写：`{card}`、`{reject}`、`{step1}`、`{ok}`。不用 `{a}`、`{1}` 这种编号。同一句里不能重名。
- **每句至少一个标记**，一般 1–4 个，列举多的句子可以到 7 个。每个标记都要有对应的画面变化；画面里用不上的标记删掉（体检命令会报「稿子里有但没有场景用到」）。
- 列举几样东西时，每样前面一个标记，画面就能跟着一个个出来：`{s1}把卡绑到 Google Play，{s2}在 App 里点订阅，{s3}以后在 Google Play 里管理。`
- 标记只是锚，不改变念法；不要把标记放在句子最末尾（后面没有词，取到的是最后一个词的时刻）。

## 六、`script.json` 的写法

```json
{
  "chapters": [
    {"id": "cold", "zh": "开场：这期讲什么"},
    {"id": "how",  "zh": "为什么走得通"}
  ],
  "items": [
    {"id": "c1", "ch": "cold", "padBefore": 0.4, "zh": "{card}这张卡，{q}到底能不能订？"},
    {"bubble": "q1", "ch": "cold", "pose": "face_shock", "dur": 2.2, "zh": "等会儿，我要看的就是这一步啊！"},
    {"id": "c2", "ch": "cold", "padAfter": 0.3, "zh": "……"},
    {"sting": "intro", "ch": "cold", "dur": 4.0},
    {"id": "h1", "ch": "how", "zh": "……"}
  ]
}
```

- `chapters`：章节按顺序列出，`id` 用短英文。一章对应一个场景文件。
- 口播句：`id` 用「章节首字母 + 序号」（`c1`、`h1`、`p1`）。`ch` 是所属章节。
- `bubble`：角色从角落探出来说一句的**无声**气泡，用来替观众吐槽或提问，`dur` 是停留秒数，`pose` 是角色的姿势名。id 一律用 `q1`、`q2`…。
- `sting`：一段不说话的垫片，`dur` 是秒数。`intro` 是通用片头（4.0 秒）、`outro` 是通用片尾（8.4 秒），其他名字（如 `credits`）是自己留给画面的空档。
- `padBefore`、`padAfter`：这一句前后额外留的秒数，只在需要给画面留时间时用（一个大动画要演完、换场前喘口气），一般 0.3–0.5。句间、换章的基本停顿配音脚本会自动加，不用每句都写。
- **所有 id 全片唯一**：口播句、气泡、垫片三类之间也不能撞。撞了会出现「b1 里没有标记 {play}」这种让人摸不着头脑的报错。
- 以模板里的示范稿为准，字段有疑问时看片场 README。

## 七、交稿前自查

写完逐条过一遍，问题改掉再进入配音：

1. 只看前三句，能不能说出这期讲什么、对我有什么用？
2. 开场说的「这期讲几件事」，后面是不是每件都兑现了、顺序一致？
3. 每个数字、按钮名、步骤，在事实表里有没有出处？
4. 对一遍 [频道规矩.md](频道规矩.md)「写稿的规矩」12 条，特别是：有没有复述官方规则或免责话、有没有承诺效果、「节点」的讲法、有没有念群号。
5. 有没有哪一句超过 60 字、哪一句没有标记、哪两句其实在重复？
6. 每一章结尾到下一章开头，观众知不知道为什么要讲下一章？
7. 把稿子从头默念一遍：有没有书面语、绕口的地方、连续三句以上同一个句式？
8. 跑 `film.cmd lint`，错误清零，警告逐条看过。「稿子里有、但没有任何场景用到的标记」虽然只是提醒，也要逐个处理：要么给它配上画面变化，要么从稿子里删掉。画面改过之后再跑一次，改画面时很容易让某个标记落空。

稿子定下后在 `制作记录.md` 记一句：章节、句数、预计时长、和派单要求逐条对应的情况。
