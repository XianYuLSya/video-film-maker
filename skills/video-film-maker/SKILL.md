# 做片子

咸鱼凌生频道的片子是**代码动画成片**：不录屏、不剪素材，稿子、画面、声音全部由代码和命令生成。这份 skill 把过去十几部片子的做法、踩过的坑、用户纠正过的事收在一起，照着做就能交出同一水准的片子。

你是谁：

- **剪辑师、场景师、审片员**（通常是 DSH 助手）：往下读，照流程做。
- **Boss**（主对话）：要把片子派出去，读 [派单模板](references/派单模板.md)；它讲怎么派、看哪几处、怎么验收。

## 这套做法的核心

```
口播稿 script.json（句子里写 {标记}）
   │  配音：一句一段合成，拿到每个字的时刻
   ▼
时间表 timing_zh.json（每句起止、每个标记的秒数、字幕）
   │  场景按「句子 id + 标记」取时间，元素在念到那个词的瞬间出现
   ▼
画面（Remotion 场景，用积木库拼）──→ 分段渲染 ──┐
声音（配乐按编排、音效跟画面动作、混音）────────┴→ 合成 MP4 + SRT
```

三条由此而来的铁律：

1. **顺序是 稿子 → 配音 → 画面。** 稿子没定不写画面；改了稿子必须重跑配音。
2. **画面里不写绝对秒数。** 所有时刻从句子和标记取，稿子怎么改画面都自动跟着走。
3. **稿子是唯一的正文。** 念什么、字幕显示什么、什么时候出什么画面，都由它决定。

## 片场

这份 skill 里的位置都用占位写，**实际路径看派单开头的「位置」一行**（Boss 派单时填本机的真值）：

| 写法 | 指什么 |
|---|---|
| `<片场>` | 片场 film-kit 的目录 |
| `<工作区>` | 频道的工作区根目录，下面有 `work\`（各部片子的工程）、`成品\`、`docs\`、`clean\` |
| `<工程>` | 这部片子的工程目录，即 `<工作区>\work\<作品名>\` |

所有工具在 `<片场>`。**开工先读它的 `README.md`**：目录地图、每条命令的用法、`film.json` 的字段都以那里为准。画面积木的用法在 `<片场>\template\film\src\blocks\手册.md`。

开一部新片：

```
& "<片场>\.venv\Scripts\python.exe" "<片场>\tools\new_film.py" "<作品名>"
```

它在 `<工作区>\work\<作品名>\` 建好工程（建在哪由片场的 `kit.local.json` 决定，脚本会打印出来），里面带一部能直接跑通的示范片（稿子、场景、配置都是规范写法，照着改）。之后所有操作都在工程目录里用 `.\film.cmd <子命令>`：

| 子命令 | 干什么 |
|---|---|
| `status` | 各步产物在不在、哪个过期了、下一步该跑什么。**不确定就先跑它** |
| `lint` | 稿子体检：结构、id、标记、念法、场景引用 |
| `voice zh` | 配音并生成时间表 |
| `art` | 把画师交的原图处理成片中素材 |
| `review zh --round r1` | 按标记自动抽帧，出图和对照清单，给审片用 |
| `stills FilmZh 12.5 30` | 抽指定秒数的帧 |
| `probe zh` | 自动量版面：出画、压字幕、字太小、重叠 |
| `render zh` | 分段渲染无声画面（可续跑） |
| `audio zh` | 配乐、音效、混音 |
| `mux zh` | 合成到成品目录，同时出 SRT |
| `check zh` | 成片体检 |
| `clip zh 0 36` | 切审看、试听片段 |
| `all zh` | 配音到体检一口气跑完 |

把 `zh` 换成 `short` 就是竖屏短版。

## 流程

每一步后面是要读的参考文档。**第一次做片子，按顺序把它们都读完再动手**；它们是这份 skill 的正文，不是可选的附录。

**0. 读派单和规矩。** 派单、创作简报、派单指到的材料全部读完。读 [频道规矩](references/频道规矩.md)。派单里的用户原话是最高依据。

**1. 开片。** 跑 `new_film.py`，读片场 README，把示范片从稿子到场景看一遍，跑一次 `.\film.cmd review zh` 看看出来的东西长什么样。工程根目录的 `制作记录.md` 已经建好骨架，之后每一步的决定、事实表、审片结论都记在里面；**每做完一步就记一笔**，这类任务很长，工作进程中断后要靠它和 `.\film.cmd status` 从断点接上。

新工程里带着示范片的稿子和场景。开始写自己的片子时：稿子直接改写 `script.json`；示范场景看完后移到工程根的 `_示范场景\`（不删，留着对照），`scenes\index.ts` 里只登记自己的场景。派单不要短版时，把 `film.json` 里的短版开关关掉（字段见片场 README），不用管 `script_short.json`。

**2. 取材和写稿。** → [写稿](references/写稿.md)
列事实表 → 定章节 → 逐句写稿、标好 `{标记}` → 自查 → `lint`。
稿子定下来立刻做两件事：按 [素材](references/素材.md) 把要画的图派出去（或列清单交上级）；向上级交「稿子节点」。交完继续往下做，不用等回复。

**3. 配音。** → [声音](references/声音.md)
把念法表配好，`voice zh`。看打印出来的时长和每章起止合不合预期。

**4. 做画面。** → [画面](references/画面.md)，以及片场的积木手册
先在 `制作记录.md` 写分镜表：每一句、每个标记对应画面上发生什么、用哪块积木。然后一章一个场景文件地写。**每写完一章就抽这一章的帧看**，不要攒到最后。

**5. 画面审片。** → [验收](references/验收.md)
全片写完，`probe` 先扫一遍机器能判断的问题，再 `review` 抽帧，**原尺寸逐张看**，记问题、改、复查，直到一轮下来没有新问题。给自己打分、找出最差三处。向上级交「审片节点」。上级会派独立审片员，意见回来后逐条处理。

**6. 出片。** `render zh` → `audio zh` → `mux zh` → `check zh`。整片渲染是最费时间的一步，所以放在审片之后。

**7. 成片体检。** 从成片里再抽帧看一遍，切试听片段。→ [验收](references/验收.md)「成片体检」

**8. 短版（派单要求时）。** → [改片与短版](references/改片与短版.md)

**9. 交付。** 按下面的格式写交付报告，更新 `制作记录.md`。

做品牌片、产品片、发布片、宣传片、logo 演绎、发布片头：**不走上面这套流程**，从 [产品片/总纲](references/产品片/总纲.md) 读起，按它第十节的顺序把 `references\产品片\` 下的文档读完，再读镜头包的手册（`film\src\cine\手册.md`），照总纲第四节的流程做。这类片子的主角是产品的真实界面，用产品片镜头包（`film\src\cine\`），按音乐的拍子排，并且必须先出风格帧、等上级确认方向再做整片。开工程在上面那条 `new_film.py` 命令后面加 `--kind product`：建出来是一部能直接跑的产品片起步工程，稿子、配置、场景、制作记录都是产品片的写法。之前走过又被否掉的那条路留档在 [品牌片](references/品牌片.md)。

改一部已有的片子：读 [改片与短版](references/改片与短版.md)，从它的步骤走。遇到报错：先看 [常见坑](references/常见坑.md) 和片场 README。

## 十条不能破的

1. 稿子里的事实都有出处；查不到的不写，或列进「未验证」。
2. 开头 20 秒讲清这期讲什么、对观众有什么用。
3. 不复述官方规则、不加免责段落、不承诺效果。
4. 画面只用积木库的视觉语言：不自己发明配色、字体、渐变、发光；人物和插画交给画师，不用代码硬画。
5. 操作画面用代码模拟加规定的假数据，标「示意画面」；真实的账号、号码、昵称、头像不进画面。
6. 不用红色圆盘配放射光芒。
7. 整片渲染之前，每一帧审片图都原尺寸看过；审片记录里没有未关闭的问题。
8. 听感和连续动态你验不了，交付时写「未验证」并附试听片段，不拿数值冒充听过。
9. 只写派单划给你的目录。不覆盖旧成片，不删文件（要清理的移到 `<工作区>\clean\`）。
10. 报告里写「完成」的每一项，都是你亲眼核过产物的。

## 什么时候停下来问

用户和上级交代的事就是授权，一直做到成片再汇报。只在这几种情况用 `ask_parent` 停下：

- 材料互相矛盾，或者关键事实查不到、绕不开；
- 要动派单划定范围以外的文件；
- 借用社区角色的设定图需要确认；
- 派单的要求和频道规矩冲突，而且看不出用户是有意破例。

工程上的取舍（用哪块积木、怎么分章、配乐怎么编）自己定，写进报告。等答复期间继续做不依赖答复的部分。

## 交付报告

成片交回时用 `report_parent(final=true)`，按这个顺序写，说人话、写具体：

```
做成了什么：成片路径、时长、分辨率帧率；字幕路径和条数；短版（如有）。
怎么验证的：体检表结果（解码、时长、响度、真峰值、字幕）；审片看了几轮、多少张、改了几处；独立审片意见处理情况。
未验证：听感（附试听片段路径和念法清单）；连续动态；稿子里没核实的事实；用到的别人的截图是否可公开。
自己定的取舍：分章、积木选择、配乐编排、和派单不完全一致的地方及理由。
还差什么：等图、等确认的事项；建议上级重点看的帧（路径）。
```

中间节点的报告同样写具体，但更短：到哪一步了、产物在哪、需要上级看什么。

## 目录

```
<工作区>\work\<作品名>\               工程（你的工作范围）
  film.json                          作品配置：成片名、念法表、配乐编排…
  film.cmd / film.py                 一条命令的入口
  制作记录.md                         事实表、分镜表、每步决定、版本记录
  film\src\script.json               口播稿（唯一正文）
  film\src\scenes\                   场景，一章一个文件
  film\src\blocks\                   积木库（随片拷来，一般不改）
  film\public\art\                   这部片子自己的图
  art\raw\                           画师交的原图
  review\<轮次>_zh\                   审片的帧、对照清单、排版体检、审片记录（短版是 <轮次>_short）
<工作区>\成品\<作品名>\               成片和字幕（README 和 发布.json 归 Boss）
<工作区>\docs\grill\<作品>\           创作简报（归 Boss，只读）
```
