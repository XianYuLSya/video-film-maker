# 视频流量工具包

做视频时找流量、定发布时间、出图、发出去，都从这里进，不用到处找。核心是开工前先用数据回答三件事：**给谁看、凭什么点开、看完去哪**。平台不公开点击率，所以整套方法靠公开的播放、粉丝、点赞、收藏、弹幕和平台规则原文，配合本频道自己的历史数据来判断。

## 位置

这份 skill 里的本机位置都写成占位，实际值由用户或派单给出（本仓库不含其中任何一个目录）：

| 写法 | 指什么 |
|---|---|
| `<工作区>` | 频道的工作区根目录，下面有 `work\`（各片工程）、`成品\`、`docs\`（创作简报、调研结论）、`clean\` |
| `<skill 目录>` | 这个 skill 装好的目录，脚本在它的 `scripts\` 下（本仓库里是 `skills\video-growth-research\`） |
| `<片场>` | 片场 film-kit 的目录（本仓库里是 `film-kit\`） |
| `<发布工具目录>` | 本机的一键发布工具目录，**不在本仓库**（见「一键发布」） |
| `<用户目录>` | 这台机器的用户目录，助手自己的配置在它下面 |

## 例行巡检：找流量密码（交给 DSH）

AI 领域变得快，热梗一两个月就换。找流量密码是简单重复的活，交给 DSH 调查员定期跑，Claude 只抽查和用结论。

- **什么时候跑**：每三天自动跑一次（用户 2026-11-11 定；Claude 桌面版的定时任务「流量巡检 · 每三天」负责派单，DSH 不花钱）。新一期开工时如果上次巡检已经超过三天，先手动派一次。
- **跑什么**：三个平台的热搜、热榜里挑 AI 相关的词；B 站按 AI 关键词抽近 30 天的样本找爆款；YouTube 按近一个月、观看数排序找爆款和小频道黑马。科普、教程、测评、整活、新闻都算，不只盯工具教程。抖音的视频数据要登录或签名才拿得到，只用热榜和浏览器能看的公开页，不登录账号、不破解签名。
- **交什么**：简报写进 `<工作区>\docs\grill\总览\调研\流量密码\<日期>.md`：这次的流量密码（附样本和数字）、新冒头的梗和叫法、三个平台的爆款表、给本频道的选题建议、和上次比的变化。仍然有效的结论合进同目录的 `流量密码速查.md`，过时的移到文末。原始数据放 `流量密码\数据\<日期>\`。
- **派单**：照 [派单模板](references/派单模板.md)「六、流量密码巡检」。连续性靠速查和上一份简报，不靠助手记忆（助手名单跟着聊天走，换个聊天就是新的）。
- **验收**：先看速查有没有被改坏，再抽两三条爆款核对数字；新冒头的梗按流程第 3 步再核一遍，才用进标题和封面。

## 交付什么

调研写进作品自己的目录（例如 `docs/grill/<作品>/调研/`），最后收口成一份「调研结论」，只留能直接用的决定：

1. **选题角度**：一句话说清这期和观众已经见过的东西差在哪。
2. **标题三个候选 + 封面方向**：封面写清大字、角色、构图。封面和要用的角色、梗图交给 Codex 画，见「封面和素材交给 Codex」。
3. **时长与结构**：开头 20 秒讲什么，每段兑现什么承诺。
4. **私域安排**：片内哪几个时点提群、简介和置顶评论原文、群里先准备好什么。
5. **要不要另剪短版**（竖屏、60 秒内），给出依据。
6. **发布时间**：正片、短版各在哪天几点发，和别的待发片子怎么错开，写进成品 README。

每条结论附依据样本（BV 号或链接、数字、抓取日期）。查不到的写「未验证」，不估数字。

## 流程

脚本都在 `scripts/bili.py`，只用 Python 标准库，默认直连 B 站，输出 json、csv 和一份 md 摘要。

### 1. 先看自己频道

```powershell
python scripts/bili.py --out <输出目录> channel <UP主mid>
```

自己频道的观众就是这期的观众，最有参考价值。看哪几条的播放/粉丝比明显高，对照它们的标题和封面跟其他几条差在哪。咸鱼凌生的 mid 是 `307427146`。

### 2. 同类样本

```powershell
python scripts/bili.py --out <输出目录> sample --kw 关键词1 --kw 关键词2 ... --since <一年前的日期>
```

关键词 10 到 15 个，覆盖：产品名和品类词、观众的痛点词、这一个月最热的梗和叫法、竞品和官方功能名。每个词取「最多播放」和「综合排序」各一页，样本到 300 条左右就够判断。重点看三处：

- **爆款表**（播放远超粉丝）：小号能爆，说明是选题和包装起的作用，不是账号体量。
- **最近 30 天扎堆的题材**：这就是当前的浪潮，标题里要用观众正在用的叫法。
- **时长分档和标题特征**：只当线索，判读注意事项见 [判读方法](references/判读方法.md)。

### 3. 找这一波的热梗和它的通行形象

观众正在用的叫法和梗，开工时往往还不知道，要从数据里滚出来：

1. **第一轮只用产品名和品类词**，`--since` 设成 30 天前。看摘要里的爆款表和播放前 20（要看更多就打开 csv 按播放排序），把反复出现的外号、梗和句式挑出来。2026-11 那次挑出的是「大肥鱼」「鱼灾」「把活甩给 DeepSeek」。
2. **把挑出的词当关键词再跑一轮**，看播放/粉丝比和发布日期：几百粉的小号也能爆、近两周还在出新稿，就是正在起的浪；只剩一两个月前的老爆款，说明已经过去了。
3. **梗的来龙去脉看官方号和复盘类视频**，分清正面和负面面向，借梗站在正面一边。大肥鱼有「鱼灾」（机器人刷评论）的一面，片子站在「让它干正经活」这边。
4. **梗里有角色，就用社区通行的形象，不自己原创。** 在 B 站搜角色名，翻播放最高几条的简介找原设计者署名，再找参考图：大肥鱼出自画师 ZipZipPipe 的 DeepSeek 女仆鲸鱼娘，参考图在 GitHub `shuaizenge/ai-girls` 的 catalog.json。用户纠正过：自创形象观众认不出来，蹭不到梗。拿到参考图交给 Codex 照着画成频道画风，片尾署名「角色设计参考 <设计者>」。

### 4. 观众声音

```powershell
python scripts/bili.py --out <输出目录> voice <BV号> <BV号> ... --words 区别,token,权限,广告,装不上
```

挑 3 到 6 条同类爆款，拉弹幕全量和热评，数关键词。高频出现的疑问（「和 xx 有什么区别」「会不会更贵」「装不上」）要在片子前段主动回答，不能等评论区问。热评接口对很多视频只回几条，量要靠弹幕。

### 5. 平台规则与私域

按 [私域引流](references/私域引流.md) 定话术和位置。核心就一条：**群是答疑、报错和版本通知的地方，不是领福利的地方**。这样既合 B 站社区公约，也让进群的人是真想用的人。

### 6. YouTube、抖音和 X（要在那边发时）

```powershell
python scripts/yt.py --out <输出目录> search --kw 关键词 --kw "English keyword" --when month --sort views --subs 30
python scripts/douyin.py --out <输出目录> hot
```

YouTube 搜索页里嵌着 `ytInitialData`，`yt.py` 解析出标题、观看数、相对发布时间（如「4 周前」，绝对日期只能估）、时长和频道，算日均观看；`--subs` 再去频道页取订阅数，算观看/订阅比找小频道爆款。搜中文内容要用中文关键词，英文词出来的多是英文和其他语种的频道。抖音只拿得到热榜，视频层面的数据靠浏览器看公开页。X 的政策页常被 Cloudflare 拦（403），政策原文可以走 web.archive.org 的快照。

**X 的帖子数据用 `scripts/x.py`**，别靠搜索引擎：搜索引擎抓到的多是官方号，2026-11-10 那条试水帖就是这么选偏的。它借一键发布工具的扩展，在用户默认 Chrome（已登录 X）里只读打开 X 搜索，会弹出一个窗口，跑完自动关。**这个工具不在本仓库**（见「一键发布」），没有它就跑不了这一步，改用浏览器手动翻 X 的搜索页看公开数据。

```powershell
$py = "<发布工具目录>\social-auto-upload\.venv\Scripts\python.exe"
& $py scripts/x.py --account XianYuLS --out <输出目录>        # 近 7 天中文 AI 高互动帖，加自己账号的关注者和最近几条
& $py scripts/x.py --latest --days 1 --q "(Claude OR GPT OR AI) lang:zh min_faves:50 since:<UTC 日期>"   # 正在起量、适合去回复的新帖
```

**在 X 上发之前先过三条**（2026-11-11 复盘：那条 Fable 5.2 新闻帖只有 12 次展示，账号当时 12 个关注者）：

1. **别人已经发过的新闻就别再发**：官方帖动辄几百万观看，中文大号几小时内就搬完了，小号再发同一条，实测只有 3–300 观看。要发就发别人拿不出来的：自己的实测（最好带视频）、一句能直接抄的技巧、本频道的老本行（订阅、封号、降智）。
2. **关注者只有两位数时，单发帖推不出去，先靠回复**：X 先拿关注者的反应决定推不推，两位数的关注者给不出这个信号。在大号刚发、正在起量的帖子下回一条有信息量的（补数字、纠错、自己踩过的坑），带蓝标的回复排得靠前。同一个中文小号同一天，自己发帖 27 观看，在 Alex Albert 帖子下的中文回复 8,548 观看。回复让用户自己在 X 里发：要快、要像人聊天，不用工具代发，程序批量回别人的帖子容易被当成垃圾号。口径看楼里的气氛：骂官方、晒封号的帖子下面，别讲官方说法、别劝人走申诉，会被当成替官方说话挨骂（用户 2026-11-11：「你这x上的官方说法说真的只会被骂」）；这种楼要么跟着吐槽，要么给马上用得上的门道。
3. **北京时间上午 9–12 点、下午 5 点前后发**：这周观看过 5 千的 48 条中文 AI 帖，发在 11 点的最多（9 条），其次 17 点、21 点，0–6 点只有 2 条。那条试水帖是本机下午 2 点半发的，正是北京时间凌晨 3 点半。用 `publish_at` 定时，别看本机时钟直接发。

**形式**：视频最吃量，上面 48 条里视频 26、图片 14、纯文字 8。开头一行就是钩子，正文按 X 的算法超过 280 就折叠成「显示更多」。信息卡别用生图模型直接出：图里带 C2PA 标记，X 会挂「由 AI 生成」，像 AI 水帖（试水帖就被挂了）；信息卡用截图或代码渲染，梗图和角色图不受影响。数字见 [结论快照](references/结论快照-2026-11.md)「X」。

### 7. 发布时间

B 站的推荐先拿一小撮人试，开头几个小时的点开和互动决定后面推不推，所以要让视频在目标观众最活跃的时段之前上线，而不是卡在峰顶才发。按这个顺序定：

1. **账号自己的「粉丝活跃时段」，这一条优先**：创作中心 → 数据中心 → 账号诊断，近 30 日数据、每天 12 点更新（官方《数据中心使用说明》）。要登录才看得到，请用户看一眼。2026-11-11 用户看过：北京时间 18 点最活跃，所以长片默认 18:00 上线。
2. **目标观众几点在看**：用同类视频的弹幕发送时间画逐小时曲线。

   ```powershell
   python scripts/bili.py --out <输出目录> timing --from <sample 输出的 json> [--top 150]
   ```

   只算发布两天后的弹幕（避开首发那波），每条视频等权。发布时刻放在曲线的上升段、离高峰还有一小时左右的地方。表里「样本几点发」那几列是按播放挑出来的视频，有选择偏差，只能参考。
3. **对一遍本频道的历史**：`channel` 的输出带发布的星期和时刻，看表现好的几条是几点发的。
4. **排期规则**（经验，官方对间隔没有任何规定）：**一天两档，中午 12:00、晚上 18:00 各一条**（用户 2026-11-11：「一天两个视频吧？中午晚上各一个」）。同一部片子的竖屏短版和正片放同一天：短版中午先发、正片晚上发（用户 2026-11-11：「短版和正片可以同一天发，短板更早，在北京时间中午，正片更长，就在北京时间晚上，这样分配就合理还舒适」）。短版片尾说「完整教程在主页」，中午时正片还没上线，所以短版简介写「完整流程在同一天 18:00 上线的正片里」加正片链接（B站上传就有 BV 号）。手上没有对应短版的那天，中午放别的短版或长片；两条长片至少隔 24 小时；周五到周日晚上留给最想推的那条。
   - **做完就排最近的一档，别让成片干等**：成片和文案齐了，就排最近的空档，一般在 1–3 天内。几条片子同时等着，按一天两档紧着往后排，赶热点的、主角正热的先发，排不下才往后顺。不拿「不赶时间」把一条推到一周以后：观众的热度和自己的流量都不等人，片子越放越旧。选题或主角改了（比如换成正热的题材），重新排一次。用户 2026-11-10 看到一条排在一周后：「为啥下周发啊？太久了吧？」
5. **提前上传、定时发布**：头一天或当天早些时候就传好，设定时公开，审核在上线前就过完，不会卡在审核里错过时段（用户 2026-11-11 提醒）。用一键发布工具的 `publish_at` 字段，见「一键发布」。定时一律填北京时间。已经定时的 B站稿件要挪时间，用本机的小脚本 `bili_edit_dtime.py`（不在本仓库）：`bili_edit_dtime.py <cookie> <BV> "2026-11-12 18:00"`（先不加 `--go` 看一眼，再加 `--go` 提交）原地改，别删了重传：重传会换 BV 号，X 帖和短版简介里的链接就断了。改完稿件会重新审核一次。
6. **发完复盘**：发布后 24 小时、72 小时各跑一次 `channel`，把播放和互动记进结论快照，下次排期用。

当前结论见 [结论快照](references/结论快照-2026-11.md)「发布时间」。

### 8. 收口

把以上结果写成「调研结论」：先写决定（上面六样），再附证据表和未验证项。写完对照本频道已有作品检查一遍：标题、封面风格是否和表现最好的那几条一致，开头是否讲清本期内容。

## 并行派活

调研量大、能拆开，适合交给 FutureAide Control 的调查员并行做：B 站样本、YouTube 与 X、选题角度（同类产品与观众质疑）、私域规则，四份各写各的文件，用 `report_parent` 交摘要。派单写法见 [派单模板](references/派单模板.md)。

调查员跑一份通常要几十分钟。这段时间主对话自己用 `bili.py` 抽样，既不空等，也能拿自己的数抽查报告里的关键数字。报告是证据，不是结论：重点核对爆款的播放和粉丝、规则条款原文、被当成结论的那几句。

## 封面和素材交给 Codex

**要出图就交给 Codex 方。** Claude 这边不出图；横竖封面、角色贴纸（各种动作表情）、梗图、场景插画，都派给 Codex 画：用 FutureAide Control 建 `target: "codex-desktop"` 的助手，它用内置的 image_gen，不用另配 API key，单张一分钟左右。用户认可它的出图质量，素材可以放开多让它生，比代码画的插画好。派单写法见 [派单模板](references/派单模板.md)「五、画师（Codex）」。

- **先锁形象**：先画一张角色设定图，之后每张都引用它；借热梗的角色把参考图和出处一起给它（找法见流程第 3 步）。
- **逐张写清**：文件名、动作或构图、背景；封面上要出现的字逐串写死，交回后自己对一遍有没有错字。
- **抠像用绿幕**：要抠的素材让它画纯绿 #00FF00 背景（它的透明底在发丝、桌椅缝里常带彩边）。实际出的是近绿色，本地按「绿比红蓝高多少」照样抠得干净（例：`<工作区>\work\<作品>\film\scripts\prep_chars.py`）。它会来问要不要做像素后处理，答「不需要」。
- **封面尺寸**：原生 1672×941 和 941×1672，B 站够用；YouTube 缩略图上限 2 MB，PNG 常超，另存 1920×1080 的 JPG。
- **模型档位**：用哪个模型、什么强度，派单前照团队配置 `<用户目录>\.config\work-workflow\团队配置.md`；表里没写画师这一行，就跟随 Codex 的默认模型。指定 model 时 effort 一起传，只传 model 会掉到该模型自己的默认强度。
- **分工**：Codex 管出图，也能替 Claude 操作剪映这类桌面软件。脚本、动画、剪辑、配音这些视频本身的活，2026-11-11 起可以交给 DSH 做：用 skill `video-film-maker`（配套片场在 `<片场>\`），Claude 当 Boss 照它的派单模板派剪辑师和审片员，自己定方向、看稿、验收；Claude 自己做片子时也用同一套片场和积木库。

## 一键发布

> **一键发布工具不在本仓库，这一节是本频道自己的用法，没有这个工具就手动上传。** 手动上传同样能走完这套流程：下面「文案」一段定标题、简介、标签，「定时」一段定发布时间，然后到各平台后台挨个传、用平台自己的定时发布。这一节里的目录、`发布.json`、`publish.py` 命令和扩展都是那个工具的东西，没有它就跳过。

成片做完，用本机的一键发布工具一次传 B站、抖音、YouTube、X：B站走 biliup，抖音在后台无窗口上传（直连），YouTube、X 走用户默认 Chrome 里的「一键发布助手」扩展。工具在 `<发布工具目录>\`，用法见它的 README，现状和限制见 `<工作区>\docs\现状\一键发布工具.md`。一个作品每个平台只传一条视频（正片发 B站、YouTube，竖屏短版可以给抖音，X 可以单独配横屏短版或竖屏短版）。抖音直接正式传，别先用试运行传一遍：同一条视频先发一条仅自己可见、再正式发，可能被当成重复内容。竖屏短版还要发 B站竖屏、YouTube Shorts 的话，在作品下面另建一个作品文件夹，比如 `成品/<作品>/竖屏短版/发布.json`，视频和封面路径写 `../xxx.mp4`，命令里作品名写 `<作品>/竖屏短版`。B站封面按 16:9 显示，竖版封面直接传会被裁，用竖版封面居中、两边垫同图模糊放大的底合成一张 1920×1080。

- **网页**：双击 `一键发布.bat`，打开 http://127.0.0.1:8790/ 。左边选作品、改文案，先「试运行」，再「一键发布」；右上角「账号」管登录和授权。
- **命令行**：用 `social-auto-upload\.venv\Scripts\python.exe` 运行 `publish.py works`（列作品）、`accounts`（登录状态）、`check <作品>`（查文案）、`publish <作品> [--only bilibili,x] [--test]`。
- **文案**：存在 `成品/<作品>/发布.json`：通用标题、简介、标签，各平台可以单独覆盖（B站标题 ≤80；抖音标题 ≤30，可以单独选竖屏版和 3:4 竖封面；X 正文中文一个字算 2，280 以内）。调研定下的标题、简介、标签直接填进去。
- **定时**：提前上传、定时公开（流程第 7 步）。`发布.json` 里写 `"publish_at": "2026-11-12 18:00"`，按北京时间解析（工具固定 UTC+8，不看本机时钟）；写在顶层就所有平台统一用，写在 `platforms.<平台>.publish_at` 里单独覆盖（比如抖音发竖屏短版，定第二天 12:00），都不写就是立即发；平台里写空字符串会退回顶层的时间，所以顶层时间已过、只想补传某个平台时，给那个平台写一个新的时间；要它传完立即公开，就把顶层时间挪进已经发过的平台里（比如 `platforms.bilibili.publish_at`），补传的平台不写。网页上有「定时发布（北京时间）」输入框和「明天 18:00」按钮，`check` 会校验格式和提前量，发布记录里状态记 scheduled。都是在平台那边定时，传完不用开着电脑等；B站传完就显示「通过审核，等待发布」，审核提前做完。工具允许的提前量：B站 10 分钟到 15 天，抖音 2 小时 10 分到 14 天，X 10 分钟到 365 天，YouTube 20 分钟到 365 天。X 和 YouTube 的定时 2026-11-11 还没完整实测；YouTube 出问题会停在点 Schedule 之前，留成草稿。
- **YouTube 每日上传上限**：测试传多了会提示「Daily upload limit reached」，要等 24 小时，或者用户在 YouTube Studio 点 Verify 做一次频道验证。
- **边界**：发布是对外的，正式发布和试运行都由用户点或明确说了才做（试运行也会在 B站、抖音留一条仅自己可见的稿子，要手动删）。Claude 可以先把 `发布.json` 填好、跑 `check`。用户说了「提前上传、定时发布」，或者排期定了让发，就是让 Claude 直接用工具传上去定时，别只填好 `发布.json` 等用户去点（2026-11-11 用户：「你好像没做吧？那几个视频的定时发布，我b站只看到一个」）。传完用 B站创作中心接口或网页核对每条是「通过审核，等待发布」。无人值守的发布定时任务（比如 YouTube 额度恢复后自动补传）会被自动模式拦下，要用户明确同意了再建。

## 判读要点

- **四个替代指标**：播放/粉丝比找爆款；赞播比看共鸣（整活类常见 3%–7%，教程类常低于 2%）；藏播比看实用（教程高，和「想装、想进群」的意愿相关）；评播比看讨论度和争议。
- **用中位数，不用平均数**：大号和搬运课程会把平均数拉偏。超长视频（一两个小时的课程合集）单独看。
- **相关不是因果**：标题带「教程」播放/粉丝比高，可能只是因为发教程的多是小号。标题特征只当线索，拿自己频道的数据再验一遍。
- **数据是快照**：所有数字写明抓取日期，下次用前重抓。

## 包装原则

来自本频道和同类样本的实测（具体数字见 [结论快照](references/结论快照-2026-11.md)）：

- **痛点加承诺，强过平铺描述。** 本频道「GPT降智？一个视频教你真正解决！」的播放/粉丝比是频道介绍片的四十倍。
- **封面大字、高对比、有角色。** 本频道素雅留白的封面表现最差，大字高对比加角色的最好。
- **蹭的是观众正在用的叫法。** 比如 2026 年 10 到 11 月 B 站管 DeepSeek Harness 叫「大肥鱼」，标题和封面用这个词，比用产品全称更容易被认出来。
- **封面挂热梗角色，用通行形象。** 那一波 B 站同类爆款（播放/粉丝比超过 200 的 13 条）里 8 条封面是蓝发女仆角色或角色短剧画面；角色照社区通行版画，找法见流程第 3 步。
- **推自己做的工具，就拿这期的制作过程当演示。** 真实派单、真实数字比编的例子可信，也顺带回答了「和已有的东西差在哪」。界面用代码模拟时，角落只写「示意画面」，别写「数据均为示例」，不然和旁白里的真实数字打架。
- **开头 20 秒讲清本期讲什么、和已有的东西差在哪。** 用户看片后专门指出过「开头没说明本期讲什么」。
- **标题要一眼就想点。** 有冲击力、有记忆点，让人刷到就忍不住点进去看看；可以玩梗，可以来点地狱笑话式的幽默（用户 2026-11-11 定：「不是狂，是有冲击力，有记忆力，让人一眼忍不住想点进去看看的那种，可以有梗，可以地狱笑话什么的幽默」）。范例是「Claude：懒鱼！Go to Work！」：短，直接用片子里自己的梗（片尾 Claude 冲大肥鱼喊的话），一句话就有画面（用户原话：「这种有梗又冲击，更舒服」）；频道最火的「10分钟速通GPT降智！！！」也是一句话就戳中痛点。要的是冲击力和记忆点，不是嗓门大：别堆感叹号和夸张词，也别写成塞满信息的说明书，装不下的搜索词放标签和简介。梗和幽默怎么玩都行，但数字照实、不承诺做不到的效果（省钱、更安全、很火这类没有数据撑就不说）；小项目在简介和正文里说明作者身份、给真实用法和限制，观众才不把它当广告。
- **一片两剪**：长片讲透（负责收藏、进群），另剪 45–60 秒短片打推荐。B 站竖屏和 YouTube Shorts 用 9:16；X 上的短片多是横屏，另出 16:9。
- **标题写观众能做的具体动作**，不堆「开源插件、多智能体编排」这类分类词，也不用「全网最全 / 最细 / 全集」。
- **画面禁忌照旧**：不用红色圆盘配放射光芒，爆发感改用漫画集中线。

## 常见坑

- 从 FAswitch 打开的会话会带 `http(s)_proxy` 指向档案端口，那个端口不一定放行 B 站，握手报 `WRONG_VERSION_NUMBER`。脚本默认直连，确实要走代理时加 `--env-proxy`。
- B 站搜索接口不带 cookie 返回 -412。脚本先访问首页拿 `buvid3`，拿不到再从 `finger/spi` 补。
- B 站搜索接口限流最严：2026-11-10 每页 0.35 秒连翻一百多页就被 HTTP 412 拦，之后两秒一页也还在冷却。脚本搜索每页隔 2 秒，被限流就等，三轮不行就停下（进度已存盘），隔几小时再跑。不换 cookie、不轮换代理或 IP 去绕限流：412 是平台的反爬风控，绕过去就是规避反爬，用户同意也不做（2026-11-10 定）；量大的活拆成小份、分几次跑。`sample` 十几个关键词只翻二三十页，没问题；`timing` 的全量模式要翻几百页，尽量用 `--from` 模式。别并发开多个。
- YouTube 大陆直连超时；FAswitch 档案端口（17911）握手失败；Windows 系统代理（当时是 127.0.0.1:7897）能通，`yt.py` 默认读系统代理。
- 抖音热榜接口时有时无：直接请求有时返回空，先打开一次首页再请求就正常。拿不到就用浏览器看，不去破解签名。
- 这台机器的时区是美东（UTC-5，冬令时），北京时间 = 本机时间 + 13 小时。脚本里的日期、时刻一律按北京时间；排发布时间、写「今天」也按北京时间，别拿本机时钟直接用。
