# 产品片镜头包 · 手册

`film\src\cine\` 是做**产品片**（品牌片、发布片、宣传片）用的一套镜头：产品的真实界面放进三维空间，带景深地拍；每个镜头一句粗重的大字；镜头之间硬转场；时间按音乐的拍子排。全部从 `cine\index.ts` 导入：

```tsx
import {B, Take, Reel, shot, track, el, cut, Float, Statement, makeTheme} from '../cine';
```

这份手册只讲**镜头怎么写**：名字、参数、范围、照抄的写法。片子**怎么想、怎么排、怎么判断好坏、哪里要停下来等人拍板**，在 skill `video-film-maker` 的 `references\产品片\`（先读那边的「总纲」）。两边说法不一致时：镜头的名字、参数、能力听这份手册；流程和过关条件听那边。

- 看效果：陈列片 `CineGallery`（67 秒，用一个虚构的浅色「仓储看板」演示，说明这套东西不绑定某个产品或深色主题）。出图：`.\film.cmd stills CineGallery 2.5 14 36`。下面每张卡的「陈列」就是它的秒数。
- 一部完整的范文：范例片工程（FAswitch 品牌片，40.6 秒、7 个镜头）。`film\src\shots\` 一个镜头一个文件，`film\src\scenes\Film.tsx` 把它们接成一卷。卡里的「范例」指的是它。
- `CineGallery.tsx` 本身也是一份能照抄的用法样例。
- **开一部产品片**：`film-kit\.venv\Scripts\python.exe film-kit\tools\new_film.py <作品名> --kind product`。建出来就是一部能直接跑的三镜头起步工程（用示例界面：数字滚动、表单、落款），配置、稿子、场景、制作记录都是产品片的写法，照着换成你的产品。

和另外两套画面库的关系：`blocks\` 是教程片积木库（纸底、弹簧、吉祥物），`brand\` 是旧的品牌片风格包（线条和图形，被用户否过，别再用）。**一部片子里不混用。**

## 通用规则

**时间**：所有组件收成片秒数 `t`（场景收到什么就传什么）。`t0` 是出现的时刻，`t1` 是退场（不写就一直在），带动作的组件用 `at`（发生的那一刻）、`land`（落地的那一刻）。**时刻一律写 `B(拍号)`**，可以加减零点几秒做细调，不写光秃秃的秒数。

**坐标**：屏上的东西（`<Screen>` 的 children）用**页面坐标**，就是截图时的 CSS 像素，直接从坐标表取：`el(page, '名字', 第几个)` 是元素的矩形，`cut(page, '名字', 第几个)` 是抠图。名字写错会直接报错并列出现有的名字。画面上的东西（大字、小标）用锁死的版位，不给坐标。

**颜色和字体**：只从 `theme` 来（`makeTheme` 从界面取色生成）。组件里没有可以填颜色的地方，除了 `Ring` 的 `color`（极少用）。强调色只给产品自己的状态和落位；扫描、取景这类「机器视线」用 `theme.info`，两者不混。

**曲线**：不传曲线就是对的。要选时只有这几条名字（`motion.ts`）：`settle` 出现和落定、`glide` 镜头移动、`drift` 长镜头里的匀速漂移、`launch` 蓄力冲出去（后面必须接硬切）、`fall` 掉回原位、`exit` 退场。**不用弹簧**；只有「按下」「落地」「图标撑开」内部带一点 3% 以内的回弹，你不用管。

**防呆**：参数越界时不会崩，会夹回安全范围，并在抽帧时（`stills`、`review`）的命令行里打一行 `[注意] [镜头包] 谁：怎么了`。看到就改，别当没看见。（整片 `render` 时不打，所以先抽帧、再渲染。）全部提醒见文末「防呆清单」。

## 一条 30–45 秒的产品片怎么搭

骨架和拍号怎么定，听 `references\产品片\分镜.md`。落到代码上是这五步，范例片就是这么搭的。用 `new_film.py <作品名> --kind product` 开的工程，这五步都已经有一份能跑的起步版（`film.json`、`script.json`、`shots\`、`scenes\Film.tsx`），你是在它上面改：

**1. 配置：按拍排时间、没有口播。** `film.json`：

```json
"versions": ["zh"],
"stings": false,
"pacing": {"gap": 0.34, "chapterGap": 0, "leadLine": 0, "leadBubble": 0, "bubbleGap": 0, "tail": 0},
"music": {
  "dir": "<你的曲库目录>",
  "grid": {"track": "techhouse", "from": "sec:0"},
  "tracks": {"techhouse": {"file": "bgm-tech-house.mp3", "beat": 0.483871, "phase": 0.0256}},
  "segments": [{"from": "beat:0", "track": "techhouse", "bar": 0}, {"from": "beat:64", "track": "techhouse", "bar": 36}],
  "duck": {"speak": -15, "gap": 0, "bubble": -6, "sting": 0, "open": 0},
  "fadeIn": 0.05, "fadeOut": 2.2, "level": -16
},
"audio": {"lufs": -14, "lufsTol": 1, "truePeak": -1.5, "alsoNoMusic": true}
```

`beat` 和 `phase` 是量出来的（见「按拍子取时间」）。片场内置记了拍长的三首（`cat`、`tonight`、`house`）可以直接当网格用：`"grid": {"track": "house", "from": "sec:0"}`，不用自己写 `tracks`（起步工程就是这么写的）。排时间只需要拍长，曲子文件不在也能跑 `voice`、`review`、`render`；到 `audio` 那一步才要文件。`grid` 说的是：全片的拍子按这首曲子走，第 0 拍在成片开头。`duck.sting` 和 `duck.gap` 设 0（垫片不是片头片尾，不压配乐）。`alsoNoMusic` 会另出一条无配乐版。

**2. 稿子：一个镜头一个垫片，写它占几拍。** `film\src\script.json`：

```json
{"chapters": [{"id": "film", "zh": "正片"}],
 "items": [
  {"ch": "film", "sting": "accounts", "beats": 22},
  {"ch": "film", "sting": "profile",  "beats": 10},
  {"ch": "film", "sting": "hero",     "beats": 10}
 ]}
```

全放在一个章节里（章节之间会被插进留白）。然后 `.\film.cmd voice zh`：没有口播也要跑这一步，它不联网，只是把时间表和拍子网格算出来。**实测结论：整片只有垫片、一句口播都没有，`voice → lint → review → probe → render → audio → mux → check` 全流程能跑通**（范例片就是这样）；`lint` 会提醒一句「场景里没有找到对稿子的引用」，那是因为产品片按拍取时间、不引用句子，可以不管。

**3. 截界面、取主题。** 见下一节。范例片的 `shots\common.ts`：

```ts
import capJson from '../cap.json';
import {CapPage, makeTheme} from '../cine';
const CAP = capJson as unknown as {pages: Record<string, CapPage>; palette: Record<string, string>};
export const PAGE = CAP.pages;
export const T = makeTheme(CAP.palette, {paper: '#f2ede5'});   // paper 是亮场的颜色，产品有自己的浅色就传
```

**4. 一个镜头一个文件。** 每个文件导出一个镜头：`defineShot({id, from, to, C, sfx, enter})`。完整的一个文件（开头的三行 import 每个镜头都一样）：

```tsx
// shots\Profile.tsx
import React from 'react';
import type {Ev} from '../kit/sfx';
import {B, Fill, Ring, Take, defineShot, el, fillSfx, ringSfx, shot, slice, track, union} from '../cine';
import {PAGE, T} from './common';

const P = PAGE.proxy;
const node = el(P, 'node');
const hero = slice(union(el(P, 'name'), node, el(P, 'submit')), 0, 0.44);   // 主角：界面上具体的一块
const NODE = {at: B(26)};                                                     // 动作的时刻写成对象，画面和音效共用
const cam = (t: number) => track(t, [
  {at: B(22), pose: shot('fromLeft', {look: hero, fill: 0.42, at: [0.29, 0.52]})},
  {at: B(30), pose: shot('fromLeft', {look: hero, fill: 0.46, at: [0.29, 0.52]}), ease: 'drift'},
]);
const C: React.FC<{t: number}> = ({t}) => (
  <Take t={t} theme={T} page={P} plate="blank" cam={cam(t)} hero={hero}
        say={{t0: B(23), layout: 'right', lines: ['起个名字，', '选一个节点。']}}
        label={{index: '02', text: 'PROFILE', corner: 'tr'}}>
    <Fill t={t} target={node} {...NODE} />
    <Ring t={t} t0={NODE.at} rect={node} />
  </Take>
);
const sfx = (): Ev[] => [...fillSfx(NODE), ...ringSfx({t0: NODE.at})];
export const Profile = defineShot({id: 'profile', from: B(22), to: B(32), C, sfx, enter: 'whipLeft'});
```

`defineShot` 只是把对象原样返回，好处是 `enter` 写错名字编辑器和 `lint` 会直接报出来。

**5. 接成一卷，登记成一个场景。** `scenes\Film.tsx`（示范场景先移到工程根的 `_示范场景\`）：

```tsx
import React from 'react';
import {Reel, ReelShot, reelSfx} from '../cine';
import {TOTAL} from '../lib/time';
import type {Scene} from './common';
import {Accounts} from '../shots/Accounts';   // …其余镜头照样 import

export const SHOTS: ReelShot[] = [Accounts, Profile, Hero, Env, Usage, AllPages, Brand];
export const FilmScene: Scene = {
  id: 'film', range: () => [0, TOTAL() + 1] as const,
  C: ({t}) => <Reel t={t} shots={SHOTS} />,
  sfx: () => reelSfx(SHOTS),
  bare: true,                                   // 整屏自管：外壳不画纸底和字幕条
};
```

`scenes\index.ts` 里 `SCENES = [FilmScene]`。之后就是片场的老一套：`.\film.cmd lint`、`review`、`probe`、`render`、`audio`、`mux`、`check`。

**改了画面再渲，必须加 `--fresh`。** `render` 判断一段要不要重渲只看时间表，看不出画面代码改没改：改了镜头直接跑 `.\film.cmd render zh`，已经渲好的段会被跳过，成片里还是旧画面（做范例片时真踩过，体检照样全绿）。它会提醒一句「跳过的 n 段是在画面代码最后一次改动之前渲的」，看到就照做：整片重渲 `.\film.cmd render zh --fresh`，或者只重渲改过的那几秒 `--from 10 --to 20`。渲完从成片里抽帧再看一遍（`sheet.py video`），别只看 `review` 的帧。

### 需要判断的地方（工具替你做不了）

下面这些锁不死，每一条都要你自己想，想不出来或拿不准就照 `references\产品片\总纲.md` 第五节停下来问：

| 判断 | 怎么判断 | 范例片怎么定的 |
|---|---|---|
| 选哪块界面当主角 | 这个镜头要证明的那句话，证据在界面上的哪几个字段？主角就是那一块，写到元素，不写「某某页」 | 「起个名字，选一个节点」→ 档案名和节点两个输入框 |
| 主陈述是哪句、放第几拍 | 官网原话里最能概括产品的一句；钉在曲子进满能量的那一拍 | 「一个档案，一个出口」，第 32 拍 |
| 每个镜头用哪个机位 | 要观众读界面上的字 → `front` / `fromLeft` / `fromRight` / `top`；只要气氛 → `graze`；相邻镜头机位和字的位置都要不同 | 贴面 → 退开 → 左斜 → 平视亮场 → 俯拍 → 左斜 → 纵深 → 落款 |
| 功能怎么演成动作 | 找这项能力的动词，让界面自己的元素把它演出来（`分镜.md` 的动词对照表） | 「各归各位」→ 账号卡落进槽位 |
| 亮场给谁 | 全片一次，给主陈述 | 第 32–42 拍 |
| 字里透什么 | 要一眼看得出里面是真界面；挑有色块、有条的区域，别挑全是小字的 | 账号卡的额度条 |

## 截界面

三维里界面文字发糊是这类片子最常见的硬伤，所以素材从一开始就按高倍截。一条命令：

```
node film/scripts/capture.mjs <截图清单.json> [只截的页面id,逗号隔开]
```

**清单**（范例片的 `ui\capture.json`，陈列片的 `cine-demo\capture.json` 是最小例子）：

```json
{
  "entry": "web/index.html",              // 本地网页入口（相对清单所在目录）；线上或本机服务写 "url": "http://127.0.0.1:5173/"
  "inject": ["demo-data.js"],             // 页面加载前注入的演示数据脚本
  "out": "../film/public/cap",            // 图写到哪（必须在 public 目录里）
  "meta": "../film/src/cap.json",         // 坐标表写到哪
  "viewport": {"width": 1240, "height": 780},
  "scale": 3,                             // 整页纹理的倍率
  "cutScale": 4,                          // 抠图的倍率
  "settle": 2600,                         // 打开页面后等多久再截（毫秒）
  "allowEmails": ["yourname@gmail.com"],  // 允许出现的演示邮箱；其余邮箱会被标出来
  "forbid": ["127.0.0.1"],                // 不该出现的词
  "palette": {"bg": "var:--bg", "accent": "var:--accent", "text": "body|color"},
  "pages": [{
    "id": "proxy",
    "steps": [{"click": "#navProxy"}, {"wait": 1200}, {"fill": {"sel": "#name", "value": "日常工作", "silent": true}}],
    "elements": {"name": "#name", "node": "#node", "submit": ".btn-primary"},
    "plates": [{"id": "blank", "css": "#name,#node{color:transparent!important}"}],
    "cutouts": [{"key": "row", "sel": ".account-row", "pad": 8}]
  }]
}
```

| 字段 | 说明 |
|---|---|
| `steps` | 截之前在页面上做的事，按顺序：`{"click": 选择器}`、`{"wait": 毫秒}`、`{"fill": {"sel", "value", "silent"}}` 填输入框、`{"select": {"sel", "value"}}` 选下拉项、`{"text": {"sel", "value"}}` 直接改一个元素的文字、`{"scroll": {"sel", "top"}}`、`{"css": "…"}`、`{"eval": "一段 JS"}`。`silent: true` 表示只改值、不触发页面的事件 |
| `elements` | 名字 → CSS 选择器。每个名字记下**所有**可见的匹配元素（所以取的时候带序号）：位置、文字、字号、字重、字体、颜色、圆角 |
| `plates` | 底板：把某些元素藏掉（`hide`: 选择器数组）或加一段 `css` 之后再截一张。要让元素离面、打字、数字滚动，都要一张把它们藏掉的底板 |
| `cutouts` | 抠图：每个匹配的元素单独截一张透明底的图，`pad` 是四周多截几像素（留给圆角和描边） |
| `palette` | 取色：`var:--变量名` 读 CSS 变量，或 `选择器\|CSS属性` 读某个元素的颜色 |
| 页面里可以单独写 `viewport`、`scale`、`cutScale`、`settle` | 覆盖全局的 |

**出四样东西**：整页纹理 `<页>.png`、底板 `<页>@<底板名>.png`、抠图 `<页>.<键>.<序号>.png`、坐标表 `cap.json`（含 `palette`）。

**演示数据脚本**里可以直接用工具提前放进页面的 `window.cap`：

- `cap.api(known, fallback)`：造一个假后端对象。`known` 里有的方法返回你给的演示数据，没有的返回 `fallback` 并记下名字（截完会在核对清单里列出「没接上的后端方法」，下一轮补）。
- `cap.fetch({'/api/list': 数据})`：拦住 `fetch`，路径包含这个键就返回这份数据。
- `cap.freezeTime('2026-11-14T09:30:00+08:00')`：把时间钉住，「3 小时后重置」这类相对时间每次截都一样。

**截完必做**：清单旁边会生成 `截图核对清单.md`，列出每页的全部可见文字，并自动标出 IP、端口、邮箱、网址、密钥样式、你列的禁用词，以及「视口比内容宽太多」（三维里会有半边空屏，照提示收窄 `viewport.width`）。**然后把每张图打开肉眼看一遍**：假数据最容易在下拉框、提示文字里露馅。

**倍率规矩**：`scale` 不低于 2，推荐 3。镜头的放大倍数超过截图倍率的 1.34 倍时 `Screen` 会提醒（字开始发虚），那就把这页的 `scale` 提高，或者别推那么近。字糊了**先查这里**，不要去调景深。

## 按拍子取时间

**量拍子**（用片场的 Python 跑）：

```
film-kit\.venv\Scripts\python.exe film-kit\tools\beat_probe.py <曲子.mp3> [--seconds 80] [--bpm 100-140]
```

打印速度、一拍多少秒、第一拍在第几秒、每 16 拍一格的能量表（看「第几拍进满」「第几拍回落」），以及可以直接贴进 `film.json` 的那一行。`--seconds` 是只用开头多少秒来量：你的片子用曲子的哪一段就量哪一段，整首一起量后半段的漂移会把起点拉偏。它用底鼓的起音找等间隔的网格；没有清楚鼓点的曲子它会说「不适合用来卡点」，那就换一首。

> 实测：范例片用的那首，它量出 123.97 拍/分、第一拍 0.011 秒；另一位设计师用 librosa 量的是 124.00、0.026 秒。两者 40 秒内的累计差不到 1 帧。另外三首已知速度的曲子（130、122、105）也都量对了。**量的是数值，不是听感**：曲子的气质合不合适，仍然要交给人听。

**在场景里**（`beat.ts`）：

| 写法 | 意思 |
|---|---|
| `B(32)` | 第 32 拍在成片第几秒（可以是小数，`B(31.5)`） |
| `beats(4)` | 4 拍有多长（秒），用在时长上 |
| `bar(8)` | 第 8 小节的第一拍 = `B(32)` |
| `beatAt(t)` | 成片第 t 秒是第几拍（审片时把秒数换回拍号） |

拍子网格的来源只有一处：`film.json` 的 `music.grid`。改了曲子或拍长，重跑一次 `.\film.cmd voice zh`，画面、配乐、音效一起跟着走。没写 `music.grid` 就用 `B()` 会直接报错并告诉你怎么写。

**配乐编排**里的 `from` / `to` 可以写 `beat:64`。要让曲子的某一段落在片子的某一拍（比如让落款坐在曲子的回落段里），就分两段，在 8 小节的整数倍上接：`{"from": "beat:64", "track": "techhouse", "bar": 36}` 是「片子第 64 拍起，放曲子的第 36 小节」。

**成片回测**（渲染合成之后）：

```
… beat_probe.py --check <成片.mp4> --beat <一拍秒数> --origin 0 --beats 2,13,32,72
```

从成片音轨里重新找鼓点，报整体偏移是多少帧（超过 1 帧返回码 2），并单独列出你点名的那几拍。`beat` 和 `origin` 在 `timing_zh.json` 的 `grid` 里。看结论以**整体偏移**为准；点名的那几拍上如果叠了音效（落地声、撞击声），它量到的可能是音效而不是鼓点，差一两帧是正常的。范例片实测：77 个鼓点，整体偏移 −0.3 毫秒。

## 镜头卡

### 机位 `shot` · `track` · `creep`

**是什么**：机位 = 一个有名字的预设 + 看哪个元素 + 它占画面多宽 + 它落在画面哪里。写出来是一句能读懂的话。

```tsx
const pose = shot('fromLeft', {look: hero, fill: 0.44, at: [0.29, 0.52]});
// 从左侧斜看 hero，它占画面宽度的 44%，中心落在画面横向 29%、纵向 52% 的位置
```

| 预设 | 样子 | 界面上的字 | 大字放哪 | 陈列 |
|---|---|---|---|---|
| `front` | 平视 | 读得清 | 旁边的暗处；字里透界面的底 | 5.0 |
| `fromLeft` | 从左侧斜看，界面往右后方退 | 读得清 | `right` | 0–5 |
| `fromRight` | 从右侧斜看，界面往左后方退 | 读得清 | `left` | 7.8 |
| `top` | 俯拍，像低头看桌上的屏 | 读得清 | `bottomLeft` | 6.4 |
| `graze` | 贴面掠过，界面变成地形 | **只当纹理** | 不放大字，只放小标 | 9.2 |
| `wide` | 退开，整块屏悬在空间里 | 读不清，看的是全貌 | `topLeft` / `left` | 10.6 |

「多页纵深」不是机位预设，是单独的组件 `Pages`（它有好几块屏，是另一个三维世界）。

**主角是横着的一整行字时**（一个输入框、表格的一行），`fromLeft` / `fromRight` 的「读得清」不成立：斜看时这一行从近到远跨过景深，一头清楚一头软，光圈收小也压不住。这种主角用 `top`（俯拍，整行离镜头一样远）或 `front`。斜看留给一张卡、一个块这种不太宽的主角。

**界面又宽又扁、放大以后占满画面、留不出放字的暗处时**：不要缩回去看整页。斜看让界面往一侧退（`fromLeft` 配 `right` 版式，`fromRight` 配 `left`），放字的那一侧自然落进暗里；主角在亮的那一侧。

| 参数 | 说明 | 范围 |
|---|---|---|
| `look` | 看哪：元素矩形（`el(...)`、`union(...)`、`slice(...)`），或一个点 `{x, y}` | — |
| `fill` | 这个元素的宽度占画面宽度多少 | 0.08–1.6；主角一般 0.35–0.6 |
| `zoom` | 直接给放大倍数（`look` 是一个点时必须给） | 0.25–6 |
| `at` | 看的那一点落在画面哪里 `[横, 纵]` | 0–1，可以略出界 |
| `tweak` | 在预设上微调角度 `{rx, ry, rz, persp}` | 每个轴 ±6°（`rz` ±3°） |
| 预设的角度、透视 | **锁死** | — |

- `track(t, [{at, pose, ease?}, …])`：一条运镜，按时刻走过几个机位。段与段之间默认 `glide`（慢起慢停），长镜头里的慢推用 `'drift'`，冲向剪点用 `'launch'`。
- `creep(pose, t, t0, t1, 0.04)`：停住的镜头极慢地推近 4%。**没有运镜的镜头都加上它**，画面才是活的。
- `union(a, b, …)` 取几个矩形的并集，`slice(r, 0, 0.44)` 取一个矩形的左边 44%（很宽的输入框只看左半段时用），`grow(r, 10)` 往外扩一圈。

**别这样**：自己凑一组角度；`tweak` 超过 ±6°（那是另一个机位了，换预设）；让镜头抖、晃、弹；要观众读字的镜头用 `graze`。

**自检**：每个镜头的落定帧上，主角是不是画面里最清楚、最亮的一块？缩到手机宽度还认得出吗？相邻两个镜头的机位和字的位置是不是都换了？

### 标准镜头 `Take`

**是什么**：一块屏 + 一个主角 + 最多一句大字，舞台、景深、打光、收尾层都替你叠好了。焦点和主光默认对着主角。**八成的镜头用它。**

```tsx
<Take t={t} theme={T} page={P} plate="blank" cam={cam(t)} hero={hero}
      say={{t0: B(23), layout: 'right', lines: ['起个名字，', '选一个节点。']}}
      label={{index: '02', text: 'PROFILE', corner: 'tr'}}>
  {/* 屏上的戏：Fill、Ring、Float、Scan、Roll… */}
</Take>
```

| 参数 | 说明 | 默认 / 范围 |
|---|---|---|
| `page`、`plate` | 哪一页、用哪张底板（不写就是整页纹理） | — |
| `cam` | 机位（`shot` 或 `track` 的结果） | 必填 |
| `hero` | 主角的矩形 | 必填 |
| `focus` | 焦点另外对在哪（主角是并排几块、想让其中一块最清楚时） | = `hero` |
| `heroLift` | 主角悬着时的高度：`floatHeight(t, DROP)` | 0 |
| `say` | 大字，参数同 `Statement`（不含 `t`、`theme`） | 不写就没有 |
| `label` | 小标，参数同 `Label`。`t0` 不写时跟着大字提前 0.2 秒出现；没有大字就从片头就在，所以没有大字的镜头要自己写 `t0` | 不写就没有 |
| `aperture` | 光圈：0 全清晰，1 很薄的焦点带 | 0.5 |
| `spot` | 视线聚拢：离主角远的角落一并变虚 | 0.25 |
| `exposure` | 屏的曝光 | 暗色界面 1.32，浅色 0.88；0.7–1.7 |
| `light` | 屏上的受光面 `{k, r, x, y}`，默认打在主角上 | `k` 1.2；0–2 |
| `stage` | 舞台的主光 `{keyAt, key, bounce, floor}` | — |
| `inside` | 画在截图上、被屏裁住的东西（`PlateFade`） | — |
| `over` | 画面层的其他东西 | — |

它会检查并提醒：主角有没有跑出画面、是不是太小、大字有没有压在主角上。

**什么时候不用它**：多块屏（`Pages`）、亮场和字里透界面（自己叠 `Stage env="light"` + `TypeWindow`）、落款（`Lockup`）、一个镜头里屏的参数要跟着时间大幅变化（照 `Accounts.tsx`、`Env.tsx` 自己叠）。自己叠的顺序固定：

```tsx
<AbsoluteFill>
  <Stage theme={T} />
  <Lens pose={pose} focus={hero}>
    <Screen page={P} pose={pose} theme={T}>{/* 屏上的戏 */}</Screen>
  </Lens>
  <Statement … /> <Label … />
  <Finish theme={T} />          {/* 最后一层 */}
</AbsoluteFill>
```

**做到位**：陈列 2.5、范例片 13.0 秒。**做坏的样子**：主角在画面外或只有指甲盖大；大字压着主角；界面比背景还暗。

### 屏 `Screen` · 景深 `Lens` · 舞台 `Stage` · 收尾 `Finish`

平时由 `Take` 替你用，自己叠镜头时才直接写。

**`Screen`**：把一页截图当成发光的面板放进空间。它保证三件事：推近后字不糊；屏被打亮但暗部不发灰（亮的字和色块更亮、往外晕一点辉光）；变换和机位的几何一致。

| 参数 | 说明 | 默认 / 范围 |
|---|---|---|
| `page`、`plate`、`pose`、`theme` | — | 必填（`plate` 可省） |
| `exposure` | 曝光 | 暗色界面 1.32，浅色界面 0.88；0.7–1.7 |
| `light` | 受光面 `{x, y, k, r}`（页面坐标） | 跟着镜头看的那一点；`k` 0–2 |
| `sheen` | 扫光位置 0→1（一条斜的高光带扫过）。**全片只给主角用一次** | 不传就没有 |
| `bloom` | 辉光 | 暗色界面 1，浅色界面 0；0–1.5 |
| `rim`、`shadow`、`radius` | 缘光、投影、圆角 | 1、1、14 |
| `inside` | 画在截图上面、被屏裁住的东西 | — |

**浅色界面**不用你改参数：`Screen` 看主题的底色自动换一套默认值（曝光压一点、不加辉光、受光面只给三成）。浅色界面本身就是画面里最亮的东西，再抬曝光、加辉光会白成一片，卡片的边都没了（陈列片整部就是浅色界面）。

**`Lens`**：景深。按机位算出焦平面和屏的交线，清晰的是一条带，带的两侧按远近分两档变虚，近处更虚。

| 参数 | 说明 | 默认 / 范围 |
|---|---|---|
| `pose` | 和 `Screen` 传同一个 | 必填 |
| `focus` | 焦点对在哪个元素 | 镜头看的那一点 |
| `lift` | 焦点离屏面的高度（主角悬着时） | 0 |
| `aperture` | 光圈 | 0.5；0–1。`graze` 用 0.55–0.7，`wide` 用 0.1–0.2 |
| `spot` | 视线聚拢 | 0；0–1 |
| `debug` | 把焦点带画出来（成片必须关） | false |

景深**不是**清晰度的解法：字糊了查截图倍率。

**`Stage`**：`env="dark"`（默认）或 `"light"`。暗场不是黑场：一盏看得见的主光、角落一抹产品色的回光。`keyAt` 主光位置、`key` 强度（0–1.6）、`bounce` 回光（0–1.5）、`floor` 地面反光带（给多页纵深）。

**`Finish`**：每个镜头最上面一层，暗角加颗粒。`vignette` 暗场默认 0.42（上限 0.7，再大四角死黑），`grain` 默认 0.05。

**自检**：屏的边缘能从背景里分出来吗？画面最暗的地方是「深」还是「死黑一片」（跑 `look_check.py` 看死黑占比）？

### 大字 `Statement` · 小标 `Label` · 补充说明 `Note`

**`Statement`**：一屏一句，最多两行，第一行亮、第二行灰（两段语气）。字底下自动压一层暗场，保证字落在干净的底上。

```tsx
<Statement t={t} t0={B(11)} theme={T} layout="topLeft" size="m"
           lines={['GPT 和 Claude，', '各自登录，|互不串号。']} sub="副句，可选" />
```

| 参数 | 说明 | 默认 / 范围 |
|---|---|---|
| `lines` | 一到两行。行内用 `\|` 切成几段依次出现。也可以写 `{text, tone: 'hi' \| 'dim' \| 'accent'}` 指定语气 | 最多两行，超了提醒 |
| `layout` | 版位：`left`、`right`、`topLeft`、`bottomLeft`、`center` | `left` |
| `size` | `xl` 128 · `l` 104 · `m` 88 | `l` |
| `sub` | 副句，一行，34–44 像素 | — |
| `enter` | `rise` 浮上来 · `wipe` 从行底推上来 · `cut` 踩着拍子直接出现 | `rise` |
| `scrim` | 字底下压暗的强度 | 1；0–1（亮场自动关） |
| 位置、可用宽度、字重 800、字距、行高 | **锁死** | — |

每个版位每行大约能放：`left` 7 个字、`right` 6 个字（`l` 字号）；`topLeft` / `bottomLeft` 10 个字；`center` 14 个字。放不下会自动缩到最小 72 并提醒你把句子改短。`topLeft` 和 `bottomLeft` 压暗的是**一整条横带**（字旁边同一高度的界面也会退掉），横带的高度跟着字块走：最后一行和副句都在暗处。

**浅色界面上不要把 `scrim` 调低。** 浅色界面上那层压暗比深色界面上显眼，像一条黑带；调低以后字后面是一层灰纱，灰字压灰底，更糟。嫌它像黑带，改的是版式和机位：优先用 `left` / `right`（界面斜着退进暗处，暗带的边是竖的，看起来是光自然落下去）；用 `topLeft` / `bottomLeft` 时，让界面被景深虚掉的那一段落在过渡区里。字后面不能有读得出的界面字，也靠机位让开。

**`Label`**：角上的等宽小标（`01 ACCOUNTS`）。它是精密感的纹理，**不要把要紧的话放这里**。`index` 编号、`text` 大写英文、`corner` 四个角（`tl` 默认）。22 像素锁死。

**`Note`**：一行居中的补充说明（跟在字里透界面后面，把那句话说完整）。`text` 里用 `*星号*` 包住要加重的字，`place` 上或下，44 像素锁死，24 个字以内。

**做到位**：陈列 53–60、范例片 6.3 / 13.0 / 22.6 秒。**做坏的样子**：三行以上；字压在清楚的界面上；字又小又细；每个镜头的字都在同一个位置。

**自检**：缩到 390 像素宽，大字和副句都读得出吗？这句话是官网原话或原话的压缩吗？

### 落位 `Float`

**是什么**：元素先悬在界面上空，到点加速落回自己的槽位，落地的一瞬底边闪一道缝。悬着的时候原位有一个虚线空槽，下面有投影（整块）或它自己的柔光（文字、图标），比屏面亮一档。

**什么时候用**：「归位、各就各位、整理好」。**全片只当一次主角。**

```tsx
const DROP = {land: B(2), height: 26, solid: true};
<Lens pose={pose} focus={hero} lift={floatHeight(t, DROP)} aperture={0.6}>     {/* 焦点跟着悬着的主角 */}
  <Screen page={A} plate="norows" pose={pose} theme={T}>
    <Float t={t} piece={cut(A, 'row', 0)} {...DROP} from={-1} />
  </Screen>
</Lens>
// 音效：floatSfx(DROP)
```

要配一张把这些元素藏掉的底板（上例的 `norows`）。

| 参数 | 说明 | 默认 / 范围 |
|---|---|---|
| `piece` | 抠图：`cut(page, 键, 序号)` | 必填 |
| `land` | 落地的时刻（写拍点） | 必填 |
| `height` | 悬浮高度（页面像素） | 20；8–48。贴面机位 20–30 |
| `fall` | 下落用时 | 0.62 秒 |
| `from` | 从什么时候开始出现 | 落地前 1.6 秒；一开场就悬着写 `-1` |
| `solid` | 带底色的整块（一张卡、一整行）写 `true` | false |
| `leave` | 到这个时刻离面飘走、淡掉（让位给另一组） | 不写就留着 |
| 下落曲线、落地缝、空槽样式 | **锁死** | — |

**做到位**：陈列 13.0（悬着）、14.5（落定）；范例片 0.6 秒。**做坏的样子**：贴面机位下把上下紧挨的两行字拆成两块先后落，悬着的那块在画面上会上移、盖住上一行，读着乱；所以**上下紧挨的东西抠成一整块**（一张卡、一个文字块）。几块依次落时，错开起点但下落过程可以重叠；别等一个完全落定下一个才动。

**一组让位给另一组**（「隔离、互不串」）：旧的一组写 `leave`（各错开 0.04 秒），新的一组在旧的走完之后再来（`from` 晚 0.25 秒以上），同时用 `inside={<PlateFade t={t} at={…} page={另一页} plate="norows" />}` 把底板换过去。两组不要同时出现在同一排槽位上。照 `Accounts.tsx`。

**自检**：悬着的那一帧，看得出它是悬着的吗（空槽、影子）？落定后和界面严丝合缝吗（连续抽帧看）？

### 表单 `Fill` · `Ring` · `Pointer` · `Press`

**是什么**：把一项功能老老实实操作一遍。这是保底的演法：不出彩，但一定不儿戏。

```tsx
const TYPE = {at: B(23) + 0.1, text: '日常工作'};
<Fill t={t} target={el(P, 'name')} {...TYPE} />                 {/* 打字：真人速度，带光标 */}
<Fill t={t} target={el(P, 'node')} at={B(26)} />                {/* 下拉框选中：直接出现 */}
<Ring t={t} t0={B(26)} rect={el(P, 'node')} />                  {/* 选中环 */}
<Pointer t={t} t0={B(28)} from={{x, y}} to={{x, y}} clickAt={B(30)} />
<Press t={t} at={B(30)} rect={el(P, 'submit')} />               {/* 按钮亮一下 */}
```

要配一张把输入框里的字藏掉的底板（清单里 `"css": "#name,#node{color:transparent!important}"`）。`Fill` 的原理是把成品截图上的那一块盖到底板的同一位置，所以字体、位置和原界面一模一样。

| 组件 | 参数 | 默认 / 范围 |
|---|---|---|
| `Fill` | `target` 输入框元素；`at`；`text`（给了就是打字）；`cps` 每秒几个字；`from` 成品是哪张图 | `cps` 6.5（**别调快**，观众看不清在干什么） |
| `Ring` | `rect`；`t0`；`keep` 亮过之后留多亮 | 0.5 |
| `Pointer` | `from`、`to`（页面坐标，光标尖的位置）；`t0` 出发；`move` 滑多久；`clickAt` 按下 | `move` 0.8 秒 |
| `Press` | `rect`；`at` | — |

`fillDone(at, text)` 是打字打完的时刻，接下一个动作用。音效：`fillSfx`、`ringSfx`、`pressSfx`。

**做到位**：陈列 18–22、范例片 11.2–14.6 秒。**自检**：自己能跟着画面操作一遍吗？点下去之后，界面的反应是紧跟着出现的吗？

### 扫描标注 `Scan`

**是什么**：一条竖线匀速扫过一排元素，扫过谁，谁就被四角取景框收紧框住、贴上标注。观众看得见因果：线到了，框才来。

**什么时候用**：「检测、检查、校验」。一排 3–5 个并列的状态最合适。

```tsx
const SCAN = {t0: B(43.5), dur: beats(4), targets: [
  {rect: el(A, 'chips', 0), tag: 'EXIT · 出口'},
  {rect: el(A, 'chips', 1), tag: 'TZ · 跟随出口'},
]};
<Scan t={t} {...SCAN} />
// 角上的计数：scanCount(t, SCAN)；音效：scanSfx(SCAN)；每个目标被框住的时刻：scanHits(SCAN)
```

| 参数 | 说明 | 默认 / 范围 |
|---|---|---|
| `targets` | 从左到右排；`tag` 是短的机器标签，`·` 之前的部分加粗 | 3–5 个，超过 6 个提醒 |
| `t0`、`dur` | 出发时刻、扫完全程用多久 | `dur` 1.5–2.5 秒 |
| 匀速、机器色、取景框的收紧 | **锁死**。扫描线是机器，不加缓动；颜色用 `theme.info`，不用产品强调色 | — |

**做到位**：陈列 25.5、范例片 22.6 秒。**做坏的样子**：线还没到框就出来了；框和标注用了产品强调色，和界面自己的状态色分不清。

### 数字滚动 `Roll`

**是什么**：界面上的数从 0 数到它在截图里的值。字体、字号、颜色都按截图时量到的来，和原界面一模一样；格式（`$`、千分位、小数位、单位）照原样。

**什么时候用**：「统计、记录、计量」。

```tsx
{U.elements.values.map((v, i) => <Roll key={i} t={t} at={B(50) + 0.35 + i * 0.09} target={v} />)}
```

清单里 `elements` 要选到数字本身（`"values": ".kpi-value"`），并配一张把它们藏掉的底板（`{"id": "novalues", "hide": [".kpi-value"]}`）。`dur` 默认 0.95 秒。一组数字一起滚时错开 0.08–0.12 秒，音效只给一声（`rollSfx`）。

**做到位**：陈列 29.0（滚到一半）、范例片 24.9 秒。**自检**：滚完的数字和整页纹理上的位置、粗细对得上吗（抽滚完后的一帧和不带 `Roll` 的整页纹理比）？

### 字里透界面 `TypeWindow`

**是什么**：巨大的字是窗口，界面在字的笔画里；洞口上沿有影子、下沿有一线高光，像在舞台上挖出来的。可以接着「冲进字里」：镜头从某一笔画冲进去，界面接管全屏，成为下一个镜头。

**什么时候用**：主陈述。**全片只用一次。**

```tsx
const WIN = {t0: B(32), through: {at: B(40) + 0.25, dur: 0.52, origin: [1110, 700] as [number, number]}};
<AbsoluteFill>
  <Stage theme={T} env="light" />
  <TypeWindow t={t} theme={T} lines={['一个档案', '一个出口']} {...WIN}>
    <AbsoluteFill style={{background: T.bg}}>
      <Screen page={A} pose={pose} theme={T} radius={0} rim={0} shadow={0} bloom={0.5} />
    </AbsoluteFill>
  </TypeWindow>
  <Note t={t} t0={B(33)} t1={WIN.through.at - 0.15} theme={T} env="light" text="节点是档案固定的出口位置，*不随人走*。" />
  <Finish theme={T} env="light" />
</AbsoluteFill>
// 音效：typeWindowSfx(WIN)
```

| 参数 | 说明 | 默认 / 范围 |
|---|---|---|
| `lines` | 一到两行，**每行最多 4 个汉字** | 超了提醒 |
| `size` | 字号 | 300；180–380 |
| `enter` | `cut` 在那一拍直接出现（配硬切）· `wipe` 从上往下揭开 | `cut` |
| `dim` | 字里的界面压暗多少：远看先读到字，再看到字里的界面 | 0.18；0–0.6 |
| `through` | 冲进去：`at` 开始、`dur` 用时、`origin` 冲入点（画面像素） | 不写就不冲 |
| children | 字里看到的那一层（铺满画面，通常是底色加 `Screen`） | 必填 |

**舞台和界面反着来**：界面是深色的，舞台用亮场（`<Stage env="light">`，`Note`、`Finish` 也写 `env="light"`），字是亮底上的暗窗口；界面是浅色的，舞台用暗场（`<Stage>`，`dim={0}`），字是暗底上的亮窗口（陈列 36.0）。界面和舞台同样深浅，字就读不出来。

**字里透什么（需要判断）**：要一眼看得出里面是真界面。挑有色块、有条、有边线的区域（进度条、卡片边、图表），平视、放大 2.5–3 倍，让它极慢地横移（每秒 5 个页面像素）。全是小字的区域透出来只是一片碎点。想更干净可以截一张把小字藏掉的底板（范例片有一张 `bars`），但别把界面感全删了。**浅色、又没有大色块的界面（一张表单）做不出干净的字里透界面**：放大了是碎字和横线，藏掉小字只剩一片灰。这种产品主陈述改用实心大字（`Statement` 的 `center` 版式、`xl` 字号，或自己叠一行更大的字），不要交一张脏的。

**冲入点 `origin`** 必须落在笔画**实心**的地方（冲进去的是「笔画里的界面」，落在空白处会冲进舞台）。先出一帧静帧，在某一笔的粗处取一个坐标。

**接下一个镜头**：冲到头界面接管全屏时，字里那块屏停在哪个机位，下一个镜头就从**同一个机位、同样的曝光**开始，转场写 `enter: 'cut'`（匹配剪辑）。范例片把这个机位导出成 `TAKEOVER`，两个镜头共用。

**做到位**：陈列 36.0（停住）、38.0（冲入）；范例片 16.8 秒、19.9 秒。**做坏的样子**：字太多太细，笔画窄到看不见里面；字里是一片碎小字；落定后不停就冲（主陈述落定后要停住，它是全片最长的一次静止）。

**自检**：缩到手机宽度先读到的是这句话吗？落定后静止了几秒？

### 多页纵深 `Pages`

**是什么**：几页界面排成一列伸向远处，脚下有反光，镜头横移、拉远。「这是一整套」的全貌镜头。

```tsx
const LIST = [PAGE.account, PAGE.usagewide, PAGE.proxy, PAGE.provider, PAGE.client];
const view = (t: number) => pagesTrack(t, [
  {at: B(58), view: {at: 0.35, dist: 620, yaw: -17, pitch: 3}},
  {at: B(66), view: {at: 1.25, dist: 1900, yaw: -11, pitch: 6}},
]);
<Stage theme={T} keyAt={[0.55, 0]} key={1.5} bounce={1.4} floor={1} />
<Pages theme={T} pages={LIST} view={view(t)} />
```

| 参数 | 说明 | 范围 |
|---|---|---|
| `pages` | 排在最前面的写在最前面。各页最好同样大小 | 3–5 页 |
| `view.at` | 盯着第几页（小数 = 两页之间） | 0 – 页数−1 |
| `view.dist` | 离多远。600 很近，1900 能看到全貌；负数是贴上去的特写 | −1900 – 4200 |
| `view.yaw` | 绕竖轴偏多少度（负 = 从左边看过去） | −34 – 14 |
| `view.pitch` | 俯仰 | −4 – 14 |
| `view.u`、`view.v` | 盯着那一页上的哪一点（0–1） | 默认页面中心 |
| 队列的间距、每块屏的角度、透视 | **锁死** | — |

`pagesPoint(view, pages, 第几页, u, v)` 算出某页上的一点落在画面哪里：镜头最后冲向某个小东西（比如左上角的徽标）接下一个镜头时，把它传给下一个镜头的 `origin`（照 `AllPages.tsx` 和 `Brand.tsx`）。

**做到位**：陈列 43.0、范例片 30.4 秒。**做坏的样子**：页面又小又暗（这场戏要有分量：最前面那页缩到手机宽度还认得出是什么）；六页以上，后面的小得认不出。

### 转场 `Reel`

**是什么**：把镜头按时间接成一卷。每个镜头写清自己「怎么进来」（`enter`），接缝的时刻就是它的 `from`，写在拍上。**没有淡入淡出这一种。**

| `enter` | 样子 | 什么时候用 | 接缝前后各占 |
|---|---|---|---|
| `cut`（默认） | 硬切 | 匹配剪辑（前后同一个机位）；字形接管之后 | 0 |
| `whipLeft` `whipRight` `whipUp` `whipDown` | 甩镜：画面朝一个方向甩出去，带方向模糊，拍后急停 | 换场景、换话题。全片不超过两次，一横一竖 | 前 0.3 秒，后 0.34 秒 |
| `push` | 推进穿越：上一个镜头朝画面里冲、变糊，下一个镜头从略大处收回来。可以给 `origin` 朝某一点冲 | 从局部进全貌；推向一个小东西接落款 | 前 0.26 秒，后 0.42 秒 |
| `flood` | 吞没：上一个镜头被一片颜色吞掉（蓄力），在拍上硬切。`color` 是吞没的颜色 | 暗场进亮场（主陈述之前） | 前 0.4 秒，后 0.14 秒 |

另外两种「接法」不经过 `Reel`：**一条镜头连下去**（同一个镜头里用 `track` 运镜，不切）；**字形接管**（`TypeWindow` 的 `through`，然后下一个镜头 `enter: 'cut'`）。

```tsx
export const Hero = {id: 'hero', from: B(32), to: B(42), C, sfx, enter: 'flood' as const, color: T.paper};
<Reel t={t} shots={[Accounts, Profile, Hero, Env, Usage, AllPages, Brand]} />
```

规矩（`Reel` 会提醒前两条）：前一个镜头的 `to` 等于后一个的 `from`；同一种转场不连用；一个接缝只用一种。甩镜时前后两个镜头会同时在画面里各待零点几秒，所以**镜头组件要经得住 `t` 比自己的 `from` 早 0.3 秒、比 `to` 晚 0.34 秒**（别在 `t < from` 时返回空）。

**做到位**：陈列 47.6 / 49.4 / 51.2 前后；范例片的六个接缝在 10.65、15.48、20.32、24.19、28.06、33.87 秒。**自检**：每个接缝连续抽帧（`--every 0.07`）看：有没有哪一帧主体被切成两半、两层画面脏叠在一起？落定的那一帧离拍点多远？

### 落款 `Lockup`

**是什么**：全片最后几秒。应用图标、字标、一句标语、网址，落定后静止。

```tsx
<Lockup t={t} t0={B(72)} end={B(84)} theme={T}
        mark="brand/mark.png" icon="brand/icon.png" word="FAswitch"
        line="账号、代理、时区，*各归各位*。" url="faswitch.futureapi.cc" note="本机运行 · 免费使用" />
// 音效：lockupSfx({t0: B(72)})
```

| 参数 | 说明 |
|---|---|
| `t0` | 图标撑开的时刻，写一个拍点。这是全片最重的一拍 |
| `icon` | 应用图标（`public` 下的路径，方的、自带底色和圆角）。**产品没有图标就不传**：只出字标，居中，`t0` 那一拍字标逐字落定，标语和网址各提前 0.6 秒。不要为了凑版式自己画一个图标 |
| `word` | 字标（产品名） |
| `line` | 标语，一行，20 个字以内；`*星号*` 包住加重的字。和官网原文一个字一个字对 |
| `url`、`note` | 网址、附注 |
| `mark` | 界面里的小徽标（透明底单色图形，会被染成浅色）。给了就先出它、翻扁、再换成图标，用来接上一个镜头。**不给的话，`t0` 之前画面是空的**，所以 `t0` 要紧跟着这个镜头的 `from`（晚一拍以内） |
| `end` | 这一场结束的时刻：全部落定后静止不足 2 秒会提醒 |
| 版式、字号、各元素出现的先后和间隔 | **锁死**：`t0−0.42` 翻扁 → `t0` 撑开 → `+0.62` 让位、字标逐字落定 → `+1.35` 标语 → `+1.85` 网址 → 静止 |

**不做的事**：徽标不晃、不眨眼、不做任何卡通预备动作。

**做到位**：陈列 65.0、范例片 37.2 秒。**自检**：字标落定后停了几秒（至少 1 秒）？全部落定后停了几秒（至少 2 秒）？网址缩到手机宽度读得出吗？

## 音效

每个带动作的组件有一个同名加 `Sfx` 的函数，参数和组件一样（不含 `t`），返回音效事件。把动作的参数写成一个对象，画面和音效共用，时刻就一定对得上：

```tsx
const DROP = {land: B(2), height: 26, solid: true};
<Float t={t} piece={…} {...DROP} />
const sfx = (): Ev[] => [...floatSfx(DROP)];
```

| 函数 | 给谁 | 声音 |
|---|---|---|
| `floatSfx(DROP, 第几个)` | `Float` 落地 | 轻的锁扣声，越往后越轻 |
| `fillSfx(TYPE)` | `Fill` | 打字是键盘声，直接出现是轻的开关声 |
| `ringSfx({t0})`、`pressSfx({at})` | `Ring`、`Press` | 开关声、按键声 |
| `scanSfx(SCAN)` | `Scan` | 扫描声，加每框住一个的一声（递减） |
| `rollSfx({at})` | 一组 `Roll` | 一声扫过 |
| `typeWindowSfx(WIN)` | `TypeWindow` | 出现时的重音；冲入时的呼啸 |
| `riseSfx({at})` | 蓄力 | 上升音，最响处对在 `at` |
| `moveSfx({at})` | 镜头自己的大动作 | 一声风 |
| `lockupSfx({t0})` | `Lockup` | 蓄力、撞击、余韵 |
| `reelSfx(shots)` | 一卷 | 各个转场的声音，加上每个镜头自己报的 `sfx()` |

这些函数只说「什么时刻、哪一类声音、多大声」，用的是片场 `kit\sfx.tsx` 里已有的类别名；具体是哪个音频文件由片场的音效表决定。**音效和配乐的文件不随片场分发**，各人放进自己工程的 `film\public\sfx\` 和曲库目录。

规矩：画面的时间线不再动了才做音效；鼓点已经在打拍子，音效只给画面上独有的动作。听感你验不了，交付时写「未验证」并切试听片段（`.\film.cmd clip zh 0 20 --audio-only`）。

## 审片工具

抽帧用片场的 `.\film.cmd review zh --round r1 --at …` / `--every 0.1 --from a --to b`（见片场 README）。产品片另外用这三个（都用片场的 Python 跑：`film-kit\.venv\Scripts\python.exe film-kit\tools\<工具> …`）：

| 要做的事 | 命令 |
|---|---|
| 一批帧拼成一张连着看（全片连看、连续抽帧看运动） | `sheet.py grid review\r1_zh --out review\r1_zh\_sheet.jpg --cols 6 --label` |
| 直接从成片抽帧拼图（成片体检；`--every 0.07 --from --to` 看一个接缝） | `sheet.py video 成品\片名.mp4 --out 全片.jpg --every 0.5 --cols 8` |
| 按 100% 裁一块看文字锐不锐 | `sheet.py crop 某帧.png --rect x,y,w,h --out 裁切.png` |
| 和通过的风格帧、和参照片左右并排 | `sheet.py pair 左目录 右目录 --out 并排.jpg --left 风格帧 --right 这一轮` |
| 量亮度 + 拼 390 像素宽的「手机视角」 | `look_check.py review\r1_zh --light hero --out review\r1_zh\_手机视角.jpg` |
| 渲染后从成片音轨回测拍点 | `beat_probe.py --check 成品\片名.mp4 --beat 0.483871 --origin 0 --beats 2,13,32,72` |

`look_check.py` 量四个数（亮度 0–100）：平均亮度（暗场低于 9 是偏暗、低于 6 手机上基本看不清）、主体亮度（画面中间）、亮部（最亮的 1% 像素，低于 40 说明字和色块都发灰）、死黑占比（超过 60% 说明大半个画面是黑的）。`--light 词` 指定文件名里带这个词的帧按亮场判。有偏暗的帧返回码 2。参考：被用户认可的那版成片，暗场风格帧平均亮度在 6.6–8.8，评审意见是「整体偏暗」；范例片的暗场镜头在 13–18。

`check`（片场的成片体检）会多查一项「音轨不是静音」：合成时选错音轨，成片是哑的，只看响度那一行容易漏。

## 渲染耗时

本机实测（范例片：40.6 秒、2439 帧、1920×1080、60 帧，七个镜头里五个带景深；`render.concurrency` 4、`chunk` 600）：

| 做什么 | 用时 |
|---|---|
| 整片分段渲染（`.\film.cmd render zh`，5 段） | **2.1 分钟**（约每帧 54 毫秒） |
| 配乐 + 音效 + 混音、合成、成片体检 | 各十几秒 |
| 抽一张静帧 | 6–8 秒（大头是打包） |
| 一轮审片抽帧（`review`，42 张） | 80 秒（每张约 1.9 秒） |
| 排版体检（`probe`，42 个时间点） | 80 秒 |

景深会把屏渲三遍（清晰一遍、两档模糊各一遍），实测并不拖慢到需要绕开的程度。想再快一点：在工程里（比如 `shots\common.ts`）加两行

```ts
import {configureCine} from '../cine';
configureCine({lens: 'draft'});
```

景深少渲一遍，虚实过渡硬一点，构图、时间、文字都不变。实测景深最重的一段（600 帧）从 42 秒降到 32 秒，快四分之一。**出成片前删掉这两行。**

## 防呆清单

命令行里看到 `[镜头包] …` 就对着这张表改：

| 提醒 | 意思 | 怎么改 |
|---|---|---|
| `shot('x')：tweak.ry=… 超出安全范围` | 微调超过 ±6° | 换一个预设，别硬掰 |
| `shot：没有叫「x」的机位` | 预设名写错 | 六个：`front fromLeft fromRight top graze wide` |
| `Screen(页)：放大到 n 倍，但这页截图只有 m 倍` | 推得比纹理还近，字会虚 | 提高这页的 `scale` 重截，或别推这么近 |
| `Screen：这个机位把界面压得很扁` | 界面上的字读不了了 | 要读字就换机位 |
| `Lens：焦点落在画面外` | 主角是虚的 | `focus` 和机位的 `look` 对同一个元素 |
| `Take：主角只有 n% 在画面里` / `主角在画面上只有 w×h 像素` | 主角出画或太小 | 调机位的 `at` / `fill` |
| `Take：大字压在主角上了` | 字和主角抢位置 | 换版位，或把主角挪到另一边 |
| `Statement：最多两行` / `放不下，已缩到 72px` | 句子太长 | 改短 |
| `TypeWindow：超出安全区，每行最多 n 个汉字` | 字太多 | 每行 4 个字以内 |
| `Scan：一次扫 n 个太多了` | 观众数不过来 | 留 3–5 个 |
| `Roll：这个元素在坐标表里没有文字` | 选择器没选到数字本身 | 改清单的 `elements` 重截 |
| `Pages：n 页太多` | 后面的页认不出 | 留 3–5 页 |
| `Reel：from 和上一个镜头的 to 对不上` / `连用了同一种转场` | 接缝会黑一下；节奏单调 | 对齐拍号；换一种 |
| `Lockup：落款全部落定后只停了 n 秒` | 没停够 | 延长这一场，或把 `t0` 提前 |
| `X 必须放在 <Screen> 里面`（报错） | `Float`、`Fill`、`Ring`、`Scan`、`Roll` 用的是页面坐标 | 放进 `Screen` 或 `Take` 的 children |
| `页面「x」的坐标表里没有元素「y」，现有：…`（报错） | 名字写错，或清单里没截 | 对着列出的名字改；没有就加进清单重截 |
| `时间表里没有拍子网格`（报错） | 用了 `B()` 但 `film.json` 没写 `music.grid` | 照「一条产品片怎么搭」第 1 步写，重跑 `voice` |

工具管不了的（要靠抽帧和 `look_check.py`、`probe` 查）：画面整体亮度、手机上读不读得清、运动连不连续、转场有没有脏帧。
